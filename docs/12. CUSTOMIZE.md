# Customize

This chapter shows how to change how compos looks and works: settings, faces, themes, keys, hooks, advice, secrets, and your own files.

## Start here

- Ask the agent. Tell it to make the font bigger, to bind a key to a command, or to use a dark theme. The agent finds the setting and saves it.
- Run `M-x customize` to pick a setting, change it, and keep it.
- Run `M-x load-theme` to change the colours. Press `C-+` and `C-_` to change this buffer's text size.
- Press `M-:` (`eval-expression`) to run one Scheme expression now.
- Put your own Scheme in `~/.compos/init.scm`. The editor loads it at start.

## Settings

A setting is a variable. It has one default. A buffer can have its own local value. A customizable variable has a saved value in `~/.compos/custom.scm`.

| Command | What it does |
| --- | --- |
| `M-x customize` | Pick a setting, set it, and save it |
| `M-x customize-set-variable` | Set one setting for this session |
| `M-x customize-save-variable` | Set one setting and keep it after a restart |
| `M-x describe-variable` | Show a variable's value and its documentation |

In Scheme, `(customize-save! 'NAME VALUE)` saves a value, `(set-default! 'NAME VALUE)` sets the default for this session, and `(variable-set! 'NAME VALUE)` sets the buffer's own value. `(customize-apropos WORDS)` finds settings by words.

Reference: [VARIABLES](<FURTHER READING/VARIABLES.md>).

## Appearance

A face is a named set of display attributes: font, colour, weight, and slant. A theme sets many faces at once.

- `M-x load-theme` lists the themes and previews one under the point. `RET` keeps it.
- `M-x dark-theme` and `M-x light-theme` switch to the dark or light pair.
- `M-x toggle-theme-monospace` draws all text in the theme's monospace font.

Text size:

| Key | What it does |
| --- | --- |
| `C-+`, `C-_` | This buffer's text larger or smaller |
| `s-)` | This buffer's normal size |
| `s-=`, `s--`, `s-0` | The whole application's text larger, smaller, normal |
| `C-M-+`, `C-M--`, `C-M-0` | More or less content in this buffer |

In Scheme, `(defface! FACE ATTR VALUE ...)` sets a default, `(define-theme NAME SPECS)` registers a theme, and `(face-attribute FACE ATTR)` reads one attribute of one face.

Reference: [FACES](<FURTHER READING/FACES.md>).

## Keys

A key runs a command. A mode can have its own keys. The same command can be on a key, in `M-x`, in the palette (`s-P`, `command-palette`), and in a chat.

| Key | Command | What it does |
| --- | --- | --- |
| `C-h k` | `describe-key` | Press a key, read what it does and which keymap binds it |
| `C-h b` | `describe-bindings` | List every key that works in this buffer |
| `C-h m` | `describe-mode` | List this buffer's mode and its keys |
| `C-h B` | `keys` | Open the keymap editor for this buffer |

In the keymap editor, `b` (`keys-rebind`) gives the command on a row another key, and `u` (`keys-revert`) takes your edit back. `M-x keys-bind` binds a command to a key everywhere. `M-x keys-unbind` takes a key away. `M-x keys-scope` filters the list by keymap.

In Scheme, `(global-set-key KEYS COMMAND)` binds everywhere and `(local-set-key KEYS COMMAND)` binds in this buffer. A package binds on its mode's map with `(mode-keys! MODE ((KEYS COMMAND) ...))`, so a reload does not stack bindings.

Reference: [KEYMAPS](<FURTHER READING/KEYMAPS.md>), [cua-mode](<FURTHER READING/cua-mode.md>).

## Hooks

A hook is a list of functions. The editor runs the list at a point, for example after a mode starts or before a save. Your own Scheme adds a function to change the editor without editing it.

```scheme
(add-hook! 'find-file-hook 'my-on-visit)
(add-hook! 'before-save-hook 'my-check-save)
(remove-hook! 'find-file-hook 'my-on-visit)
```

Give `add-hook!` the quoted name of a function. Adding the same name again does nothing. A local hook runs only in one buffer.

Reference: [HOOKS](<FURTHER READING/HOOKS.md>).

## Advice

Advice wraps a named function. The function does not need a hook. Each registration has a name, so you can inspect it, disable it, enable it, or remove it.

```scheme
(advice-add! 'some-function 'after 'my-name 'my-handler)
(advice-disable! 'some-function 'my-name)
(advice-enable! 'some-function 'my-name)
(advice-remove! 'some-function 'my-name)
```

The position is `before`, `after`, or `around`. An `around` handler receives `NEXT` and the arguments, and can change them or skip `NEXT`. Prefer a hook when one exists. Use advice when the seam is a function and you cannot edit it.

Reference: [ADVICE](<FURTHER READING/ADVICE.md>).

## Secrets

`M-x setup-secrets` probes the secret tools on this machine and sets one up. The editor reads a key from the environment first, then from the key files in `~/.compos`, then from Doppler. `M-x setup` stores each key with the tool you choose.

The tools are Doppler, 1Password, GPG, macOS Keychain, and Linux Secret Service. In Scheme, `(keychain-secret-get SERVICE)`, `(secret-tool-get SERVICE)`, and `(op-secret-get "op://VAULT/ITEM/FIELD")` read one. `(register-llm-key! PROVIDER VALUE)` sets an explicit key for a model provider. Set `secret-provider` to add your own lookup after these.

Never paste a secret into a buffer, a chat, or a commit.

Reference: [1. SETUP](<1. SETUP.md>).

## Your files

| Path | What it holds |
| --- | --- |
| `~/.compos/init.scm` | Your own Scheme. The editor loads it at start, after the bundled packages. |
| `~/.compos/ai-config.scm` | Presets and connectors for chats and agents. |
| `~/.compos/custom.scm` | Settings that `M-x customize` saved. |
| `~/.compos/packages/` | Your own packages. |
| `~/.compos/desktop.etf` | The saved buffers, windows, groups, and point. |

Do not edit `custom.scm` by hand. Use `M-x customize`, so it keeps its format.

## Groups and their config

A group can have its own `group.scm`. `M-x group-config` opens it, and `M-x group-reload-config` loads it again into every buffer in the group. It holds the group's directory, layout, default bundle, and its own keys. `M-x group-cwd`, `M-x group-llm`, and `M-x group-sandbox` set the common ones.

Reference: [groups](<FURTHER READING/groups.md>), [GROUP-MODES](<FURTHER READING/GROUP-MODES.md>).

## For the agent

- Change only the setting, face, or key the user names. Ask before a wider change.
- Find a setting with `(customize-apropos WORDS)` or `(apropos WORDS)`. Read it before you change it.
- Save with `(customize-save! 'name value)`. Do not use `set!`; it may not reach the live callback.
- Read the new state back: the variable, the face attribute, or `(key-binding KEYS)`.
- Never read, print, or store a secret value. Name the secret, not its value.
