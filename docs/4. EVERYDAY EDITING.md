# Everyday editing

This chapter covers the keys and commands for moving, finding and changing text: files, search, undo, the rings, registers, bookmarks, the prefix argument, completion, the two palettes, menus, text size and the two optional edit styles (cua and Vim).

## Start here

- `M-x` runs a command by name. `s-p` (Cmd-P) finds a command by what it does.
- `C-x C-f` opens a file, and `C-x C-s` saves it.
- `C-s` searches forward as you type, and `C-r` searches backward.
- `C-/` undoes one change. Press it again to undo more.
- `C-SPC` sets the mark, so a motion selects text. `C-w` cuts it and `C-y` pastes it.

## Files

compos works like Emacs: the buffer is the text you edit, and a file buffer follows its file on disk.

- `find-file` opens a path you type, with completion of the names in the directory. A path that does not exist makes a new buffer, and the first save writes it.
- A file buffer follows its file. When git, a formatter or another program changes the file, the editor merges the change into the buffer and keeps your unsaved work. A save merges first.
- When you and the file changed the same line, the save stops. `M-x save-buffer-anyway` writes over the file.
- `M-x revert-buffer` reads the file from disk again and discards your edits.

| Key | Command | What it does |
| --- | --- | --- |
| `C-x C-f` | `find-file` | Open a file in this window |
| `C-x 4 f` | `find-file-other-window` | Open a file in the other window |
| `C-x C-s` | `save-buffer` | Save this buffer to its file |
| `C-x C-w` | `write-file` | Write the buffer to a new file |
| `C-x C-d` | `dired` | Prompt for a directory and browse it |

Reference: [HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## Dired

Dired lists the files of a directory. `C-x C-d` opens it.

- `RET` opens the file at point in another window. A directory opens in place.
- `SPC` or `m` marks a row. A command then acts on every marked row.
- `x` runs the command on the marked rows.
- `^` opens the parent directory.

| Key | Command | What it does |
| --- | --- | --- |
| `RET` | `dired-visit` | Open the file at point |
| `M-RET` | `dired-open` | Open the file and go there |
| `q` | `dired-quit` | Go back through the directory history |
| `g` | `dired-revert` | Read the directory again |
| `^` | `dired-up` | Open the parent directory |
| `R` | `dired-rename` | Rename or move a file |
| `C` | `dired-copy` | Copy a file |
| `+` | `dired-mkdir` | Make a directory |
| `SPC` | `list-mark` | Mark the row at point |

Reference: [LISTS](<FURTHER READING/LISTS.md>), [HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## The project

A project is a directory under version control. These commands read the project of the current buffer and leave out the files that git ignores.

| Key | Command | What it does |
| --- | --- | --- |
| `C-x p f` | `project-find-file` | Find a file in the project |
| `C-x p g` | `project-ripgrep` | Search the project text |
| `C-x p d` | `project-dired` | Open dired at the project root |
| `C-x p p` | `project-switch-project` | Enter another project group |

`project-ripgrep` shows each match as a row. Move through the list to preview a match, and press `RET` to go to it.

Reference: [HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## Search in a buffer

`isearch` searches as you type. Point moves to the first match at once. Press the same key again for the next match.

| Key | What it does |
| --- | --- |
| `C-s` | Search forward as you type, and again for the next match |
| `C-r` | Search backward as you type, and again for the previous match |
| `RET` | Stop at the match |
| `C-g` | Go back to where you started |

compos has no separate `occur` command. To list matches in a buffer, use `isearch`, or `M-s t` (`occur-ts`) to list the captures of a tree-sitter query. To list matches in a project, use `C-x p g` (`project-ripgrep`).

Reference: [HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## Replace

| Key | Command | What it does |
| --- | --- | --- |
| `M-%` | `query-replace` | Replace literal text, one match at a time |
| `M-x replace-string` | `replace-string` | Replace every literal match, with no questions |

At each match, press `y` to replace it or `n` to skip it. Press `C-g` to stop the run.

Reference: [HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## Go to a place

| Key | Command | What it does |
| --- | --- | --- |
| `M-g g` | `goto-line` | Go to a line number you type |
| `M-<` | `beginning-of-buffer` | Go to the start |
| `M->` | `end-of-buffer` | Go to the end |
| `s-i`, `M-g i` | `imenu` | Go to a definition in this buffer by its name |

`imenu` reads the structure of the buffer. In a file with more than one kind of definition, it has a tab for each kind.

Reference: [HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## Undo

One command is one undo step. The editor keeps the history of each buffer.

| Key | Command | What it does |
| --- | --- | --- |
| `C-/`, `C-x u`, `s-z` | `undo` | Undo the last change |
| `s-Z`, `C-M-_` | `undo-redo` | Redo the change that undo took back |

After a run of undos, the next `undo` reverses them: that is redo. `undo` takes a count like the motion commands, so `C-u 3 C-/` undoes three steps.

Reference: [COMMANDS](<FURTHER READING/COMMANDS.md>), [C-u](<FURTHER READING/C-u.md>).

## The kill ring

Kill commands put text on the kill ring. `yank` puts the newest entry at point.

| Key | Command | What it does |
| --- | --- | --- |
| `C-k` | `kill-line` | Kill from point to the end of the line |
| `C-w` | `kill-region` | Kill the region |
| `M-w` | `copy-region-as-kill` | Copy the region, without killing it |
| `M-d` | `kill-word` | Kill forward to the end of the word |
| `M-DEL` | `backward-kill-word` | Kill backward to the start of the word |
| `C-y` | `yank` | Paste the newest kill |
| `M-y` | `yank-pop` | Replace the paste with an older kill |

A kill command that follows a kill command grows the newest entry. Three `C-k` presses yank back as one piece.

The browser handles Cmd-C and Cmd-V. They use the system clipboard. The kill ring is separate and stays inside the editor.

Reference: [COMMANDS](<FURTHER READING/COMMANDS.md>).

## The mark ring

The mark is a saved place. A region is the text between the mark and point.

| Key | Command | What it does |
| --- | --- | --- |
| `C-SPC`, `M-SPC` | `set-mark-command` | Set the mark here |
| `C-u C-SPC` | `set-mark-command` | Go to the previous mark and pop the ring |
| `C-x C-SPC` | `pop-global-mark` | Go to the last mark set in any buffer |
| `C-x C-x` | `exchange-point-and-mark` | Swap point and mark |

Each buffer keeps its own mark ring. A separate global ring goes back across buffers, so a jump can land in another file.

Reference: [COMMANDS](<FURTHER READING/COMMANDS.md>).

## Registers

A register is one character that holds text or a place.

| Key | Command | What it does |
| --- | --- | --- |
| `C-x r SPC` | `point-to-register` | Save point and the buffer |
| `C-x r j` | `jump-to-register` | Go to the saved point, or restore saved windows |
| `C-x r s` | `copy-to-register` | Save the region as text |
| `C-x r +` | `append-to-register` | Add the region to the saved text |
| `C-x r i` | `insert-register` | Insert the saved text at point |
| `C-x r w` | `window-configuration-to-register` | Save the frame windows |
| `C-x r v` | `view-register` | Say what a register holds |

Registers stay with the desktop, so they come back after a restart.

Reference: [COMMANDS](<FURTHER READING/COMMANDS.md>).

## Bookmarks

A bookmark has a name and a place. It lasts after a restart.

| Key | Command | What it does |
| --- | --- | --- |
| `C-x r m` | `bookmark-set` | Set or replace a bookmark here |
| `C-x r M` | `bookmark-set-no-overwrite` | Set a bookmark only if the name is free |
| `C-x r b` | `bookmark-jump` | Go to a bookmark by name |
| `C-x r l` | `list-bookmarks` | Show the bookmark table |

The bookmark table is a list. `RET` visits the row, `/` filters, `SPC` marks, `d` flags a bookmark for delete, and `x` deletes it.

Reference: [LISTS](<FURTHER READING/LISTS.md>), [HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## The prefix argument

`C-u` sets one value for the next command only. The command reads it in one of two ways.

| Keys | Raw value |
| --- | --- |
| `C-u` | `(4)` |
| `C-u C-u` | `(16)` |
| `C-u 3`, `M-3` | `3` |
| `C-u - 2` | `-2` |
| `M--` | `-` |

A count multiplies. `C-u 8 C-n` moves eight lines. A flip is a yes or no, and the value does not matter. `C-u` and `C-u 17` mean the same.

The plain key is the common answer. `C-u` asks for the other answer. Examples: `C-x C-f` visits a file in this group, and `C-u C-x C-f` asks which group. `C-SPC` sets the mark, and `C-u C-SPC` goes back to the previous mark.

The value belongs to the frame, so two browser tabs are two users. It also survives `M-x`: `C-u M-x foo` gives `foo` the same value that a key would.

Reference: [C-u](<FURTHER READING/C-u.md>), [COMMANDS](<FURTHER READING/COMMANDS.md>).

## Completion

Every prompt narrows its list as you type. The default match style is flex: one term is a subsequence, and several terms are substrings in any order.

| Key | What it does |
| --- | --- |
| `M-p` | Put the previous remembered item in the input |
| `M-n` | Put the next remembered item in the input |
| `RET` | Choose the selected item |
| `C-g` | Cancel the prompt |
| `M-/` | Complete the text around point |
| `C-M-i` | Complete the text around point |

Each prompt keeps its own history across sessions. Some modes offer completion while you type. These settings control it:

| Setting | Default | Meaning |
| --- | --- | --- |
| `completion-auto` | `#t` | Offer completions while you type |
| `completion-auto-delay` | `150` | Milliseconds of quiet before it asks |
| `completion-auto-prefix` | `2` | Fewest characters before point |

Reference: [COMPLETION](<FURTHER READING/COMPLETION.md>).

## The two palettes

The editor has two ways to name a command.

| Key | Command | What it answers |
| --- | --- | --- |
| `M-x` | `execute-extended-command` | What is the command called? |
| `s-p` | `command-palette` | How do I do this? |

`M-x` searches command names. Each row shows the key of the command, and the page shows what the command does. Type a part of the name and press `RET`.

`s-p` (Cmd-P) searches by the words of the task, including the everyday words people use. It puts the commands you ran first. Words that name no command go to a model, which picks one. A plain sentence can also bind a key, for example `bind C-x C-g k to group-kill`.

With `vscode-mode` on, Cmd-P finds a project file and Cmd-Shift-P (`s-P`) opens the palette. Run `M-x vscode-mode` to toggle it.

For a plain search of the whole editor, press `C-h a` (`apropos`). For a task, press `C-h h` (`how-do-i`).

Reference: [COMMANDS](<FURTHER READING/COMMANDS.md>), [KEYMAPS](<FURTHER READING/KEYMAPS.md>).

## Menus

A transient is a short menu of related commands. It shows over the buffer, and the buffer stays selected. The menu owns the keys until you leave it.

| Key | What it does |
| --- | --- |
| `RET` | Run the selected row |
| `<up>`, `<down>`, `C-p`, `C-n` | Select a row |
| `<left>`, `<right>` | Move between menu columns |
| `?` | Show the docstring of each row |
| `C-g`, `ESC` | Close the menu |
| `C-q` | Close every open menu |
| `C-x C-s` | Save the menu settings |

Menus appear where a command has several values to set at once. `C-c b` (`llm-configure`) is one: it sets the backend, the model and the effort. App modes use menus too, such as the todo actions and the tabs of a site app.

Reference: [KEYMAPS](<FURTHER READING/KEYMAPS.md>), [MODES](<FURTHER READING/MODES.md>).

## Text size

The size of the text belongs to the buffer.

| Key | Command | What it does |
| --- | --- | --- |
| `C-+`, `s-+` | `text-scale-increase` | Make this buffer larger |
| `C-_`, `s-_` | `text-scale-decrease` | Make this buffer smaller |
| `s-)` | `text-scale-reset` | Give this buffer the normal size |
| `s-=` | `ui-scale-increase` | Make the whole application larger |
| `s--` | `ui-scale-decrease` | Make the whole application smaller |
| `s-0` | `ui-scale-reset` | Give the whole application the normal size |
| `C-M-+`, `C-M-=` | `content-scale-increase` | Show more of this buffer: one level in |
| `C-M--` | `content-scale-decrease` | Show less of this buffer: one level out |
| `C-M-0` | `content-scale-reset` | Show this buffer at the normal level |

`text-scale` changes the font size of one buffer. `ui-scale` changes the size of every buffer in the frame. `content-scale` changes how much detail a structured buffer shows.

Reference: [HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## Visual line wrap

Long lines can wrap on the screen. `visual-line-mode` wraps them and makes the vertical motions follow the rows the reader sees, not the source lines.

- The mode is on in prose modes, such as morg and writing, and in web pages.
- There is no key. Run `M-x visual-line-mode` to toggle it in the current buffer.
- `<up>`, `<down>`, `<home>` and `<end>` move by rendered row. A run of vertical moves keeps the goal column.
- The browser measures where each row begins. Scheme decides what each key means.

Reference: [VISUAL-LINE-WRAP-MAP](<FURTHER READING/VISUAL-LINE-WRAP-MAP.md>), [MODES](<FURTHER READING/MODES.md>).

## cua-mode

Shift with a motion key selects text. That is the whole of `cua-mode`, and it is on from boot.

| Key | Extends the region |
| --- | --- |
| `S-<left>`, `S-<right>` | One character |
| `S-<up>`, `S-<down>` | One visual line |
| `S-<home>`, `S-<end>` | To the start or the end of the line |
| `C-S-<left>`, `C-S-<right>` | One word |
| `M-S-<left>`, `M-S-<right>` | One word on the macOS keyboard |
| `C-S-<home>`, `C-S-<end>` | To the start or the end of the buffer |
| `S-<prior>`, `S-<next>` | One screen |
| `s-a` | The whole buffer |

Run `M-x cua-mode` to toggle it.

The Shift chords work in a buffer you edit. In a buffer you have just landed on, they keep their plain meaning until the first key that says you are editing there. Press `ESC` or `C-g` to return to that movement state.

A chat buffer refuses cua-mode. Use `C-SPC` to start a region there.

cua-mode does not own the Emacs keys. `C-a`, `C-e`, `C-k`, `C-f`, `C-b`, `C-n`, `C-p`, `C-d`, `M-f`, `M-b`, `C-y`, `M-w`, `C-w` and `C-SPC` work in every buffer, and turning cua-mode off takes none of them away.

Reference: [cua-mode](<FURTHER READING/cua-mode.md>), [KEYMAPS](<FURTHER READING/KEYMAPS.md>).

## Vim keys

`evil-mode` gives the buffer Vim keys. Run `M-x evil-mode` to toggle it everywhere, or `M-x evil-local-mode` to toggle it in one buffer. To make it stick, put `(evil-mode-on!)` in `~/.compos/init.scm`.

- The states are normal, insert and visual. The cursor shows the state.
- Motions, operators, counts, `/` and `?` search, and the ex commands `:w`, `:q`, `:wq` and `:e FILE` work.
- Special buffers, such as chat, dired, mail and terminals, keep their own keys.
- The mode is not yet complete: repeat with `.`, macros, named registers and marks are not there.

Reference: [MODES](<FURTHER READING/MODES.md>), [KEYMAPS](<FURTHER READING/KEYMAPS.md>).

## For the agent

- Work on buffers by name. Do not move the user's windows, point, mark or focus.
- Use `M-x` and `s-p` to discover commands. Use `C-h a` (`apropos`) to search the catalog, and `C-h h` (`how-do-i`) for a task.
- Read a key with `(key-binding KEYS)`. Read every key of a command with `(where-is-internal COMMAND)`. The live editor wins over an older doc.
- A test names the command, never a production key. Bind your own keys to test a binding.
- The prefix argument is frame-local and lasts for one command. Read a count with `'p` and a flip with `'P`, never both.
- Add a setting with `defcustom` and read `docs/COMPONENTS.md` before you choose a menu.
- The full task list is in [HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>). The keys in force are in [KEYS](<FURTHER READING/manual/KEYS.md>). The rules of the keymap ladder are in [KEYMAPS](<FURTHER READING/KEYMAPS.md>).
