# Writing

This chapter covers writing and reading documents in compos. It explains Markdown and Morg pages, fenced blocks, TODO states and the agenda, annotations, PDFs, the writing workspace, slide decks, and made images.

## Start here

- A `.md` file opens as a rendered page. Press `⌃c ⌃v` to see and edit the source.
- In a Morg page, `Tab` folds a heading or a code block, and `⌃c ⌃c` runs the code block under point.
- `⌃c ⌃t` changes a heading's TODO state. `⌃c A` opens your agenda.
- `⌃c ! a` adds a note to a document. `⌃c ! l` lists its notes.
- `⌥x write` opens the writing workspace: the document, a scratch, and the document's chat.

## Markdown pages

A file that ends `.md` or `.markdown` opens in `morg-mode`. The first visit shows the rendered page, not the source. The page is drawn on the buffer's own rows: markup is hidden, pictures and tables are drawn, and the caret stays on the source text.

| Key | What it does |
| --- | --- |
| `⌃c ⌃v` | Show the rendered page, or the source |
| `Left`, `Right` | Choose the raw or preview tab in the header line |
| `Enter` | Add a line; a list item continues, an empty item ends the list |
| `⇧Enter` | Add a soft line break |

`⌥x preview-font-toggle` switches every rendered page between serif and monospace. The settings `preview-font-family`, `preview-font-size`, and `preview-measure` set the type.

A picture on its own line, with a line of emphasis under it, draws a figure with a caption. An image and a YouTube URL alone in a paragraph draw as a picture or a card. A `table` fence colors its cells by rules on the fence, such as `green>=.7` or `red<.4`.

Reference: [MARKDOWN](<FURTHER READING/MARKDOWN.md>).

## Folding and moving in Morg

`morg-mode` is Markdown with org habits. Folding lives in a buffer-local, so it survives a daemon restart.

| Key | What it does |
| --- | --- |
| `Tab` | Fold the heading or code block at point |
| `⇧Tab` | Fold the whole file to an overview, or show all |
| `⌃c ⌃n`, `⌃c ⌃p` | Next or previous heading |
| `⌃c ⌃f`, `⌃c ⌃b` | Next or previous heading at this level |
| `⌥↓`, `⌥↑` | Next or previous landmark (heading, paragraph, block, link) |
| `⌥n`, `⌥p` | Next or previous link |
| `⌃c Space` | Select the block at point, else the section |
| `⌃x n n` | Show only the heading at point |
| `⌃x n N` | Narrow the view and the LLM context to the same section |
| `⌃x n w` | Show the complete document |

Reference: [MORG-DEMO](<FURTHER READING/MORG-DEMO.md>).

## TODO states and the agenda

`⌃c ⌃t` cycles a heading between no state, `TODO`, and `DONE`. The agenda collects dated headings from the files and directories in `morg-agenda-files`. `morg-agenda-days` sets how many days it shows.

`⌃c A` opens the agenda. Each day is a card. `n` and `p` step over entries, `Tab` folds a day, and `Enter` opens the entry's file. `[` and `]` move by one week, and `.` returns to today. `g` reads the files again, and `⌃c ⌃v` shows the plain listing.

Reference: [MORG-DEMO](<FURTHER READING/MORG-DEMO.md>).

## Fenced blocks

A fenced block is code between two lines of three backticks. In a Morg page, `Tab` folds the block and `⌃c ⌃c` runs it. The result lands in a `result` fence under the block, and a second run replaces the result.

| Fence | What it does |
| --- | --- |
| `sh`, `bash`, `zsh` | Run the body and put the output in a result fence |
| `elixir`, `python`, `node`, `ruby` | Run the body with that program |
| `scheme` | Run the body in the editor's own interpreter |
| `llm`, `ask`, `chat` | Send the body to the buffer's model |
| `csv` | Preview the first lines as a table; `:lines N` sets the count |
| `table` | Draw colored cells from rules on the fence |
| `diff`, `patch` | Paint as a diff; it does not run |
| `result`, `result-csv`, `result-scheme` | Hold output; they do not run |

`⌃c ⌃x` writes every block with a `:tangle PATH` header to its file, in document order. A `:show-source PATH::NAME` block is filled from the named definition when you press `⌃c ⌃c`.

Reference: [BLOCKS](<FURTHER READING/BLOCKS.md>), [MORG-DEMO](<FURTHER READING/MORG-DEMO.md>).

## Asking the model inside a document

Press `⌃Enter` in a Morg paragraph to send the document to its model. The answer streams below the block at point as a quote whose first line is `> [!agent]`. With `⌃u`, `⌃Enter` asks where the reply goes: at point, in the document's chat, or in a new document. The quote is ordinary text, so it survives a save and a reopen.

With point in a reply, its own keys act on it:

| Key | What it does |
| --- | --- |
| `c` | Copy the reply without the quote marks |
| `e` | Make the reply your own prose |
| `r` | Ask the model again and replace the reply |
| `d` | Dismiss the reply |
| `s` | Split the reply into a chat of its own |
| `Enter` | Start an answer below the reply |
| `Tab` | Fold the reply to its first line |
| `n`, `p` | Next or previous reply |
| `⌃x n n` | Show only the reply |

`⌥o` opens the document's chat. In the writing workspace, `writing-model` and `writing-instructions` choose the model and the standing instruction.

## Org files

A file that ends `.org` opens in `org-mode`, a separate outline mode written in Scheme. A headline starts with stars, and a checkbox starts with `- [ ]`.

| Key | What it does |
| --- | --- |
| `Tab` | Fold the headline at point |
| `⇧Tab` | Overview or show all |
| `⌃c ⌃t` | Cycle the TODO state |
| `⌥Enter` | Add a headline at this level |
| `⌃Enter` | Add a headline after the subtree |
| `⌥←`, `⌥→` | Promote or demote a headline (or de-dent a line) |
| `⌥⇧←`, `⌥⇧→` | Promote or demote the subtree |
| `⌥↑`, `⌥↓` | Move the subtree |
| `⇧↑`, `⇧↓` | Change the priority |
| `⌃c ⌃c` | Toggle a checkbox and recount its cookies |

`⌃c ⌃v` shows an org file as a rendered page, as it does for Markdown.

Reference: [ORG-MODE-PLAN](<FURTHER READING/internal/ORG-MODE-PLAN.md>).

## Notes on a document

`annotate-mode` adds margin notes to any text document. Put point on a line or select a region, then press `⌃c ! a` and type the note. A note anchors to its text and follows it through edits, so it keeps its place when the text above changes.

| Key | What it does |
| --- | --- |
| `⌃c ! a` | Add a note on the region or the line |
| `⌥n`, `⌥p` | Next or previous note |
| `⌃c ! m` | Show or hide the note margin |
| `⌃c ! l` | List the notes in `*annotations*` |

The notes list has one row per note. `Enter` visits a note, `r` resolves it, `d` dismisses it, `R` replies to it, and `s` asks an agent for a suggested fix. `y` applies that fix. The `Left` and `Right` keys change the tab, which filters notes by who wrote them.

A file inside a project keeps its notes in a store file in that project. A file outside a project keeps them under the compos home. The notes are on disk, so a restart brings them back.

Reference: [ANNOTATIONS](<FURTHER READING/ANNOTATIONS.md>).

## PDF documents

Open a PDF with `⌥x pdf-open` or a document link. The file opens in `pdf-reader-mode`, which shows one page as a picture.

| Key | What it does |
| --- | --- |
| `n`, `p` | Next or previous page |
| `Home`, `End` | First or last page |
| `+`, `-` | Grow or shrink the page |
| `0` | Reset the size |
| `i` | Change the page theme |
| `g` | Reload the page and its data |
| `q` | Close the window |

`⌥x pdf-edit-mode` creates a generated copy and edits that copy. The original file never changes. `pdf-edit-delete-page`, `pdf-edit-duplicate-page`, `pdf-edit-move-page-forward`, and `pdf-edit-move-page-backward` change the copy. `pdf-edit-undo` and `pdf-edit-reset` restore it.

Notes on a PDF are not supported yet. The annotate layer works on the text of a buffer, and a PDF page is a picture. The design for it is in the reference.

Reference: [PDF-ANNOTATIONS](<FURTHER READING/internal/PDF-ANNOTATIONS.md>).

## The writing workspace

`⌥x writing-mode` toggles distraction-free composition in the current buffer. It centers the text to `writing-measure`, hides the line numbers, turns on visual lines, and shows a word count and a read time in the modeline. `writing-wpm` sets the reading speed. Typography and preview stay separate.

`⌥x writing-layout` opens the companion workspace as three panes: the document, its scratch buffer, and the group chat. `⌥x write` turns on writing mode and opens that layout together. `⌥x count-words` reports the words in the buffer.

Paste an image into a Morg or writing buffer and the editor asks where to save it. It writes the file and inserts a Markdown image link. The link is relative to the document when both are in the same project.

## Slide decks

A deck is a Markdown document. Press `⌃c ⌃s` in a Morg page to present it in the other window. `⌥x slides-new` starts a new deck from the starter deck, and `⌥x slides-demo` presents the demo.

In the deck, a line of `---` starts the next slide, and a `+` list item is a step that waits for a key. `???` starts speaker notes. An HTML comment sets a transition, a background, or a layout, as in `<!-- transition: cube -->`. The front matter sets the theme and the title.

The presenter page has the keyboard. `->` or `Space` steps on, `<-` steps back, `o` shows every slide, `f` uses the whole frame, `b` blacks out, and `?` lists the keys. `s` shows the notes. `⌃g` gives the keyboard back. In the deck, `⌃c ⌃n` and `⌃c ⌃p` step, `⌥↓` and `⌥↑` move by slide, and `⌥⇧↓` and `⌥⇧↑` select slides.

## Made images

`⌥x image-generate` asks for a prompt and makes a PNG from it. The file lands in `image-gen-directory` and opens in the other window. The image job uses the `image` role in `llm-model-presets`, or `image-gen-default-model` when the role is empty. OpenAI and Gemini are the known providers. The settings `image-gen-size` and `image-gen-quality` shape an OpenAI image.

## For the agent

- Read a Markdown file with `markdown-outline`, `markdown-find`, and `markdown-read`. Edit it with `markdown-replace!` and `markdown-insert-after!`.
- Read a fenced block with `block-list`, `block-at-line`, and `block-text`. Edit the source text with the buffer calls.
- Name a command, not the key that runs it. Keys move.
- The live editor is the truth. Read the live mode doc with `(mode-doc "morg-mode")` and the command docstrings when a design note is out of date.
- The full rules for fenced blocks are in [BLOCKS](<FURTHER READING/BLOCKS.md>). The page rules are in [MARKDOWN](<FURTHER READING/MARKDOWN.md>).
