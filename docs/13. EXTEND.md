# Extend

This chapter shows how compos grows: new commands, modes, keys, hooks, components, blocks, apps, and workflows, all in Scheme.

## Start here

- Elixir supplies the mechanism. Scheme decides the policy. So a new feature is almost always Scheme.
- The bundled packages are in `scheme/packages/`. Your own are in `~/.compos/`.
- Press `Option-:` (`eval-expression`) to run one expression now. A saved package reloads with no restart.
- Ask the agent to build an app or a command. It writes the Scheme in the live editor.
- Before you name a function, run `(apropos WORDS)` to find the real one.

## Packages

A package is one `.scm` file. The loader stamps its package and namespace. `priv/init.scm` lists every bundled package in dependency order. `~/.compos/init.scm` loads your own.

| Command | What it does |
| --- | --- |
| `Option-x package-list` | List the installed user packages |
| `Option-x package-install` | Fetch a package from a URL and load it |
| `Option-x reload-file` | Reload one Scheme package into the live session |
| `Option-x reload-scheme` | Reload the Scheme tree |

`(load NAME)` searches `load-path`: priv, its packages, the project's `scheme/packages`, the config home, and its packages.

Reference: [ARCHITECTURE](<FURTHER READING/ARCHITECTURE.md>).

## Commands

A command is a name, a docstring, and a function. `Option-x`, a key, the palette, an agent, and a test all run a command by name.

```scheme
(define-command "my-greet" "Say hello in the echo area" (interactive)
  (lambda () (message "hello")))
```

A command takes arguments from the key that runs it or from a prompt. `(interactive 'p)` takes the prefix argument, `'r` the region, `"sPrompt: "` a string. `(command-call NAME ARG ...)` runs one with explicit arguments.

Reference: [COMMANDS](<FURTHER READING/COMMANDS.md>).

## Modes

A major mode is a name, a setup function, a keymap, and a hook. A buffer wears one major mode and any number of minor modes.

```scheme
(define-mode "my-mode" (lambda () (setq-local! 'truncate-lines #t)))
(define-derived-mode "my-child-mode" "my-mode" (lambda () ...))
(register-minor-mode! "my-minor-mode" setup teardown "my-minor-mode-map")
(set-mode! "my-mode")
```

`define-mode` creates the keymap `NAME-map` and the command `NAME`. A setup rebuilds keys, overlays, and folds from the locals it finds, so it runs on every entry, on restore, and on reload. `auto-mode-alist` decides which mode a file opens in.

Reference: [MODES](<FURTHER READING/MODES.md>).

## Keymaps

A keymap has a name, its own bindings, and a parent. A key goes down a ladder: the thing at point, the minor modes, the buffer's mode, then the global map.

```scheme
(mode-keys! "my-mode" '(("C-c g" "my-greet")))
(minor-mode-keys! "my-minor-mode" '(("M-<left>" "backward-word")))
(define-key "ctl-x-map" "g" "my-greet")
(bind-prefix! "mode-specific-map" "m" "my-map")
```

Bind on the mode's map, never on a buffer, when the binding belongs to the mode. The keymap editor is at `Ctrl-h B` (`keys`).

Reference: [KEYMAPS](<FURTHER READING/KEYMAPS.md>).

## Hooks

A hook is a list of functions that the editor runs at a seam.

```scheme
(add-hook! 'find-file-hook 'my-on-visit)
(add-hook! 'my-mode-hook 'my-setup #t)
(remove-hook! 'find-file-hook 'my-on-visit)
```

Give `add-hook!` the quoted name of a function. A reload that redefines the function changes what runs, and adding the name again is a no-op. A keyed hook, `(add-hook! '(block-click diff) FN)`, keeps one function per key.

Reference: [HOOKS](<FURTHER READING/HOOKS.md>).

## Components and ComposML

A component is a ready view: a card, a table, a row, a key bar. Search before you build.

```scheme
(apropos-components "foldable heading")
(describe-component 'ui/card)
(component 'ui/card '((title "Changes") (open? #t) (body (...))))
```

`Option-x component-gallery` shows every component with its example. ComposML is the semantic HTML that the browser client renders. Scheme blocks become ComposML elements; the client never runs editor logic. A package adds a component with `defcomponent`.

Reference: [COMPONENTS](<FURTHER READING/COMPONENTS.md>), [COMPOSML](<FURTHER READING/COMPOSML.md>), [COMPOSML-COMPONENTS](<FURTHER READING/COMPOSML-COMPONENTS.md>).

## Blocks

A fenced block in a Morg document has a kind. One registration gives the kind its paint, its runner, and its keys.

```scheme
(define-fence-kind! "mermaid" "Draw the body as a diagram." 'runnable #t
  'run (lambda (buf b lang body) ...))
```

`Ctrl-c Ctrl-c` runs the block at point. `Option-x morg-execute-block` does the same. In Scheme, `(block-list BUF)` finds the blocks, `(block-at-line BUF LINE)` finds one, and `(block-text BUF LINE)` reads it.

Reference: [BLOCKS](<FURTHER READING/BLOCKS.md>), [MARKDOWN](<FURTHER READING/MARKDOWN.md>).

## Apps

An app is a listing with one row per thing, a detail buffer for each row, and the same actions on both, opened by one command. Because every app uses the same list mode, the same keys mark, filter, and act everywhere.

Ask the agent for a new app. It loads the app-creator skill and writes the Scheme while the editor runs. For example: make me a Sentry app, with a button that asks an agent to fix an issue.

Reference: [10. APPS](<10. APPS.md>), [COMPONENTS](<FURTHER READING/COMPONENTS.md>).

## Workflows

A workflow is Scheme that reacts to events. It has a name, the topics it listens to, a key to group by, and a handler.

```scheme
(define-workflow! "my-triage"
  'listen   '("mail:inbox:*")
  'group-by 'thread
  'handle   'my-triage-handler)
```

A workflow runs on its own lane, never on the UI lane, so a keystroke does not wait for it. Its state is the event log, so a restart costs nothing.

Reference: [EVENT BUS](<FURTHER READING/EVENT BUS.md>).

## Skills

A skill is a saved procedure that the agent loads for a recurring job. A chat loads one with `/NAME`, and `(skill NAME)` gives its instructions in Scheme. `Option-x chat-show-skills` lists the skills of this chat.

The bundled skills are in `apps/compos_core/priv/skills/`. Your own live in `.claude/skills/` or `~/.compos/skills/`.

Reference: [PROMPTS](<FURTHER READING/PROMPTS.md>), [AGENT CONTEXT MANAGEMENT](<FURTHER READING/AGENT CONTEXT MANAGEMENT.md>).

## Try it live

| Key or command | What it runs |
| --- | --- |
| `Option-:` (`eval-expression`) | One expression from the minibuffer |
| `Ctrl-x Ctrl-e` (`eval-last-sexp`) | The expression before point |
| `Option-x eval-region` | The region |
| `Option-x eval-buffer` | The whole buffer |
| `Option-x reload-file` | One saved package |

A change takes effect at once. Saving a `.scm` file reloads only the top-level forms whose text changed. A compile error changes nothing. A restart is needed only for a new dependency, a supervision tree change, a NIF rebuild, or a renamed door.

## Watch out

| Trap | The true thing |
| --- | --- |
| `'()` is truthy | Test with `pair?`, not with truthiness |
| `(buffer-local-value NAME BUF)` | The variable comes first, as in Emacs |
| `buffer-save!` with a path | It takes no arguments; run it in `with-current-buffer` |
| `(substring S START)` | It needs three arguments |
| `(map F A B)` | `map` takes one list; zip first |
| `(cons 1 2)` | It raises; use a two-element list for a pair |
| `(string->number "x")` | It answers `:error`, not `#f` |

## For the agent

- Add Elixir only for a NIF, a socket, a PTY, a parser, a scheduler, or raw buffer mechanics. Every other feature is Scheme.
- Stamp each public definition with `(domain! 'NAME)` and `(effects! '(LEVEL))`. Use one level: `pure`, `read`, `write`, or `destroy`.
- Search the catalog before you invent a name or a component. A name we invent says the verb and its direction, with no package prefix.
- Test the kernel in `priv/tests` and a package beside it as `NAME-test.scm`. Run `bin/test-fast` before a commit.
- Two hot-reload rules: a new state field of a long-lived GenServer is read with `Map.get/3` and written with `Map.put/3`; a file that captures a primitive before shadowing it uses `alias-once!`.
