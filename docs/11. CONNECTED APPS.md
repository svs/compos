# Connected apps

This chapter shows the outside services that compos brings into the editor. For each service it gives what the service does, the command that opens it, and the setup or secret it needs.

## Start here

- Every connected service is an app: a list with one row per item, a detail page, and the same keys on both.
- Open a service with its command: `M-x google`, `M-x notmuch` or `M-x mail`, `M-x whatsapp`, `M-x irc`, `M-x feeds`, `M-x sentry`, `M-x linear`, `M-x browse`, `M-x spotify`. Load the iMessage package first, then run `M-x imessage`.
- Most services need one connection or one key the first time. Ask the agent to set it up.
- A secret comes from the environment, a key file, Doppler, or a secret setting. Do not put a secret in a package.
- The Chrome extension connects your own browser. Browsing with your logins, Spotify, and page snapshots need it.
- When a service fails, `C-h e` shows the message that names the missing key or connection.

## Mail

Mail is a local notmuch index. compos reads the index, shows threads, tags them, replies, and sends.

| Command | What it does |
| --- | --- |
| `M-x mail` | Show mail in this group: index, thread, and chat in three panes |
| `M-x notmuch` | Open the mailboxes, the saved searches |
| `M-x notmuch-inbox` | Open the index on the default query |
| `M-x notmuch-search` | Run a notmuch query |
| `M-x notmuch-switch-host` | Read mail from another mailbox |

Setup: install the `notmuch` program and let it index your mail. Sync is external; use lieer or mbsync and a cron job. compos never fetches mail by itself. The send command is `msmtp -t` by default; set your own routes in `notmuch-send-routes` in `~/.compos/init.scm`.

The mail store can live on another machine. Add each host and profile to `notmuch-mailboxes`; a call then runs `notmuch` there over ssh.

Keys in the list: `RET` opens the thread, `n` and `p` move and preview, `a` archives, `d` trashes, `r` replies, `/` filters, and `g` refreshes. In a thread, `r` replies and `a` archives. In a draft, `C-c C-c` sends and `C-c C-k` aborts.

Reference: [manual/HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>), [EVENT BUS](<FURTHER READING/EVENT BUS.md>).

## Google Workspace

Google is native OAuth, not a browser scrape. It opens Gmail, Calendar, Drive, Docs, Sheets, Slides, Contacts, and Tasks as lists and documents in the editor.

| Command | What it does |
| --- | --- |
| `M-x google` | Open the Google application list |
| `M-x google-connect` | Connect another account with OAuth |
| `M-x google-account` | Choose the default account for new buffers |
| `M-x google-disconnect` | Revoke an account's access |
| `M-x google-operation` | Prepare an editable API request |

Setup: create a Desktop app OAuth client in Google Cloud. Enable the APIs you use and download the client JSON. Put the file at `~/.compos/google-client.json`, or give the JSON to Doppler as `GOOGLE_OAUTH_CLIENT_JSON`. Then run `M-x google-connect` and complete consent in your browser.

Each account stays separate. Run `M-x google-connect` again to add another account. A new account never replaces an old one.

Keys: `RET` opens a row, `g` refreshes, `s` searches, `]` and `[` page, and `/` filters. `c` composes mail. Drive lists use the Dired keys.

Reference: [features/GOOGLE](<FURTHER READING/features/GOOGLE.md>).

## WhatsApp

WhatsApp is an MCP service. A server holds the WhatsApp connection, and compos draws its chats as an app.

| Command | What it does |
| --- | --- |
| `M-x whatsapp` | Open the WhatsApp workspace |
| `M-x whatsapp-list` | Show the recent chat index |
| `M-x whatsapp-reply` | Reply to the selected message or chat |
| `M-x whatsapp-refresh` | Read the chat list again |
| `M-x whatsapp-feed-start` | Turn new messages into events |

Setup: register an MCP server named `whatsapp` and make a preset that holds it. Add both forms to `~/.compos/ai-config.scm`:

```scheme
(mcp-register! 'whatsapp (list 'type "http" 'url "https://HOST/mcp"))
(define-preset! 'whatsapp "Read and reply to WhatsApp" '(whatsapp))
```

The server supplies the message tools, including `list_messages` and `send_message`. Replace the URL with your server's address.

Keys: `RET` reads a chat, `r` replies, `/` filters, `g` refreshes, and `q` quits.

Reference: [EVENT BUS](<FURTHER READING/EVENT BUS.md>).

## iMessage and SMS

iMessage reads the conversations that Messages keeps on this Mac. A reply goes out through Messages.

| Command | What it does |
| --- | --- |
| `M-x imessage` | Open the iMessage workspace |
| `M-x imessage-list` | Show the recent chat index |
| `M-x imessage-reply` | Send to the selected chat |
| `M-x otp` | Copy the newest one-time code from Messages |

Setup: the package is bundled but it does not load at boot. Add one line to `~/.compos/init.scm`:

```scheme
(require 'imessage)
```

Give compos Full Disk Access in System Settings, because it reads `~/Library/Messages/chat.db`. Turn on Text Message Forwarding on the iPhone to include SMS.

There is no key. Keys: `RET` reads a chat, `r` sends, `/` filters, `g` refreshes, and `q` quits. `M-x otp` looks back `otp-minutes` minutes, 15 by default.

## IRC

IRC is a client in the style of rcirc. Every server, channel, and private conversation has its own buffer.

| Command | What it does |
| --- | --- |
| `M-x irc` | List your servers; `RET` connects |
| `M-x irc-servers-add` | Add a server |
| `M-x irc-servers-remove` | Remove the server on this row |
| `M-x irc-servers-connect` | Connect the server on this row |
| `M-x irc-toggle-verbose` | Show every server line, or only what people say |

Setup: edit `irc-servers`. Each entry has a name, host, port, optional nick, and optional channels to join. The default list has libera and oftc. There is no secret in the entry; a server that needs a password or a registered nick asks for it with a command.

At the prompt, a line goes to the channel. A line that starts with `/` is a client command, such as `/join`, `/part`, `/msg`, `/me`, `/nick`, and `/quit`. An unknown command goes to the server as a raw command.

## Feeds

Feeds reads RSS and Atom subscriptions in one list, newest first.

| Command | What it does |
| --- | --- |
| `M-x feeds` | Read every subscribed feed |
| `M-x feeds-subscribe` | Subscribe to a feed, or to a page that has one |
| `M-x feeds-unsubscribe` | Remove a feed |
| `M-x feeds-refresh` | Fetch every feed again |

Setup: none. The fetch uses `curl` and `xsltproc`. Subscriptions live in `~/.compos/feeds`, one URL per line, and the read links live in `~/.compos/feeds-read`.

Keys: `RET` reads an item, `o` opens it in the real browser, `a` subscribes, `d` unsubscribes, `g` refetches, and `/` filters.

Reference: [manual/HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## Sentry

Sentry lists unresolved production errors for one project and one environment. A row opens a structured detail page, and the same actions work on the list and the page.

| Command | What it does |
| --- | --- |
| `M-x sentry` | List unresolved issues |
| `M-x sentry-open` | Show the issue detail |
| `M-x sentry-ask-agent` | Send the issue to the Sentry group agent |
| `M-x sentry-open-web` | Open the issue in Sentry |
| `M-x sentry-resolve` | Resolve the issue after confirmation |

Setup: put a Sentry auth token in `SENTRY_AUTH_TOKEN` in the environment, in a key file, or in Doppler. Set `sentry-org`, `sentry-project`, and `sentry-environment` to your values. The defaults name a sample organization and project.

Keys: `RET` opens the detail, `SPC` marks, `a` asks the agent, `o` opens the web page, `R` resolves, `/` filters, and `g` refreshes.

## Linear

Linear shows issues under status tabs, with one page per issue. The same keys act on the row and on the page.

| Command | What it does |
| --- | --- |
| `M-x linear` | Open your issues |
| `M-x linear-group-defaults` | Pin this group's list to a team, project, and assignee |
| `M-x linear-webhook-setup` | Let Linear push every issue and comment change to compos |

Setup: make a personal API key in Linear under Settings, Security and access. Give it to compos in one of three places: the secret setting `linear-api-key`, the environment variable `LINEAR_API_KEY`, or the file `~/.compos/linear-key`.

Keys: `RET` opens the issue, `s` sets status, `a` sets assignee, `p` sets priority, `c` comments, `n` makes a new issue, `o` opens it in Linear, `/` filters, and `g` rereads. The left and right arrows step the status tabs.

## Web pages

Browse fetches a page, removes the site furniture, converts it to Markdown, and shows it in a read-only buffer with browser-like keys.

| Command | What it does |
| --- | --- |
| `M-x browse` | Read a URL or a search as text |
| `M-x browse-other-window` | Read a page in another window |
| `M-x browse-page` | Show the live page itself |
| `M-x browse-history` | List every page you read |
| `M-x browse-learn-parser` | Learn this site's parser again |

Setup: the pipeline uses `curl`, `pandoc`, `readable`, and `xsltproc`. The Chrome extension gives the best fetch, because it uses your logins and runs page scripts.

A site parser is an XSLT sheet at `~/.compos/packages/web/parsers/HOST.xsl`. It removes menus, footers, and other furniture before the text is made. With `browse-learn-parsers` on, the first read of a new host learns a parser in the background.

Keys: `RET` follows a link, `TAB` moves to the next link, `l` goes back, `g` refetches, `R` toggles the calm and full reading, `o` opens the real browser, `H` opens the history, and `q` quits.

Reference: [BROWSE](<FURTHER READING/BROWSE.md>).

## Your Chrome

The extension connects compos to your own Chrome. It gives M-x and C-x on any page, a `compos` address, and calls that read a page with your logins.

| Command | What it does |
| --- | --- |
| `M-x list-tabs` | Show the browser's open tabs |
| `M-x switch-to-tab` | Bring a browser tab to the front |
| `M-x browser-mode` | Allow or refuse agent browser access for this workspace |

Setup: open `chrome://extensions`, turn on Developer mode, choose Load unpacked, and select `~/.compos/chrome-extension`. `M-x setup` walks the same steps and shows when the extension has connected. `(browser-connected?)` answers the same from Scheme.

A new compos build rewrites the extension folder. Press the reload arrow on the extension card to load the new copy.

Reference: [CHROME_EXTENSION](<FURTHER READING/CHROME_EXTENSION.md>).

## Spotify

Spotify is a website app. It reads the web player with your signed-in session, and it plays music in your own player tab or the desktop app.

| Command | What it does |
| --- | --- |
| `M-x spotify` | Open Home, Liked Songs, Playlists, and Search |
| `M-x spotify-play` | Play the row, track, or page at point |
| `M-x spotify-open` | Open the item beside the list |
| `M-x spotify-search` | Search Spotify |
| `M-x spotify-now-playing` | Say what plays and redraw the player bar |

Setup: install the Chrome extension and sign in to the Spotify web player in Chrome. There is no API key and no OAuth. Set `spotify-user` to your user id so the Playlists section can read your profile.

Reference: [CHROME_EXTENSION](<FURTHER READING/CHROME_EXTENSION.md>).

## Kindle

The Kindle package uses a jailbroken Kindle as a second screen. `M-x kindle-dashboard` draws today's and tomorrow's calendar with the weather as a greyscale image, sends it over ssh, and shows it. The sleep screen reads the same file.

| Command | What it does |
| --- | --- |
| `M-x kindle-dashboard` | Draw the dashboard and show it on the Kindle |
| `M-x kindle-dashboard-sync` | Send a fresh dashboard in the background, for a cron job |

Setup: this is a user package, not a bundled one. Load it from `~/.compos/packages` in `~/.compos/init.scm`. The Kindle runs KOReader's SSH server. Set `kindle-host`, `kindle-port`, `kindle-key`, and `kindle-weather-place`.

## Add another service

Ask the agent. A new service is an app in Scheme: a list, a detail page, and actions on both. When the service speaks MCP, register the server and add a preset. When it has a REST or GraphQL API, write a small package with a key setting and a list mode. The editor reloads the package while it runs.

Reference: [COMPONENTS](<FURTHER READING/COMPONENTS.md>), [EVENT BUS](<FURTHER READING/EVENT BUS.md>).

## For the agent

- Name the opening command from this chapter. Do not guess a key and do not assert a production binding in a test.
- A service needs one of three doors: a local program, an MCP server, or an HTTP API. Pick the smallest one that does the job.
- A secret goes through `key-get`, `secret-value`, or a `defcustom` with `'type 'secret`. Never print it and never write it into a package or a commit.
- MCP servers and presets belong in `~/.compos/ai-config.scm`. A server is `mcp-register!`; a preset is `define-preset!` with the server names.
- A new app follows the app shape in [10. APPS](<10. APPS.md>). Test it through `KeyDispatch.handle_key/1` with keys you bind yourself.
- When a service disagrees with these pages, the live editor wins. Run `(apropos WORDS)` and `(command-names)` first, then fix this page and log the stale text.
