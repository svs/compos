# Everyday editing

This chapter covers the keys and commands for moving, finding and changing text: files, search, undo, the rings, registers, bookmarks, the prefix argument, completion, the two palettes, menus, text size and the two optional edit styles (cua and Vim).

## Start here

- `⌥x` runs a command by name. `⌘p` (Cmd-P) finds a command by what it does.
- `⌃x ⌃f` opens a file, and `⌃x ⌃s` saves it.
- `⌃s` searches forward as you type, and `⌃r` searches backward.
- `⌃/` undoes one change. Press it again to undo more.
- `⌃Space` sets the mark, so a motion selects text. `⌃w` cuts it and `⌃y` pastes it.

## Files

compos works like Emacs: the buffer is the text you edit, and a file buffer follows its file on disk.

- `find-file` opens a path you type, with completion of the names in the directory. A path that does not exist makes a new buffer, and the first save writes it.
- A file buffer follows its file. When git, a formatter or another program changes the file, the editor merges the change into the buffer and keeps your unsaved work. A save merges first.
- When you and the file changed the same line, the save stops. `⌥x save-buffer-anyway` writes over the file.
- `⌥x revert-buffer` reads the file from disk again and discards your edits.

| Key | Command | What it does |
| --- | --- | --- |
| `⌃x ⌃f` | `find-file` | Open a file in this window |
| `⌃x 4 f` | `find-file-other-window` | Open a file in the other window |
| `⌃x ⌃s` | `save-buffer` | Save this buffer to its file |
| `⌃x ⌃w` | `write-file` | Write the buffer to a new file |
| `⌃x ⌃d` | `dired` | Prompt for a directory and browse it |

Reference: [HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## Dired

Dired lists the files of a directory. `⌃x ⌃d` opens it.

- `Enter` opens the file at point in another window. A directory opens in place.
- `Space` or `m` marks a row. A command then acts on every marked row.
- `x` runs the command on the marked rows.
- `^` opens the parent directory.

| Key | Command | What it does |
| --- | --- | --- |
| `Enter` | `dired-visit` | Open the file at point |
| `⌥Enter` | `dired-open` | Open the file and go there |
| `q` | `dired-quit` | Go back through the directory history |
| `g` | `dired-revert` | Read the directory again |
| `^` | `dired-up` | Open the parent directory |
| `R` | `dired-rename` | Rename or move a file |
| `C` | `dired-copy` | Copy a file |
| `+` | `dired-mkdir` | Make a directory |
| `Space` | `list-mark` | Mark the row at point |

Reference: [LISTS](<FURTHER READING/LISTS.md>), [HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## The project

A project is a directory under version control. These commands read the project of the current buffer and leave out the files that git ignores.

| Key | Command | What it does |
| --- | --- | --- |
| `⌃x p f` | `project-find-file` | Find a file in the project |
| `⌃x p g` | `project-ripgrep` | Search the project text |
| `⌃x p d` | `project-dired` | Open dired at the project root |
| `⌃x p p` | `project-switch-project` | Enter another project group |

`project-ripgrep` shows each match as a row. Move through the list to preview a match, and press `Enter` to go to it.

Reference: [HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## Search in a buffer

`isearch` searches as you type. Point moves to the first match at once. Press the same key again for the next match.

| Key | What it does |
| --- | --- |
| `⌃s` | Search forward as you type, and again for the next match |
| `⌃r` | Search backward as you type, and again for the previous match |
| `Enter` | Stop at the match |
| `⌃g` | Go back to where you started |

compos has no separate `occur` command. To list matches in a buffer, use `isearch`, or `⌥s t` (`occur-ts`) to list the captures of a tree-sitter query. To list matches in a project, use `⌃x p g` (`project-ripgrep`).

Reference: [HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## Replace

| Key | Command | What it does |
| --- | --- | --- |
| `⌥%` | `query-replace` | Replace literal text, one match at a time |
| `⌥x replace-string` | `replace-string` | Replace every literal match, with no questions |

At each match, press `y` to replace it or `n` to skip it. Press `⌃g` to stop the run.

Reference: [HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## Go to a place

| Key | Command | What it does |
| --- | --- | --- |
| `⌥g g` | `goto-line` | Go to a line number you type |
| `⌥<` | `beginning-of-buffer` | Go to the start |
| `⌥>` | `end-of-buffer` | Go to the end |
| `⌘i`, `⌥g i` | `imenu` | Go to a definition in this buffer by its name |

`imenu` reads the structure of the buffer. In a file with more than one kind of definition, it has a tab for each kind.

Reference: [HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## Undo

One command is one undo step. The editor keeps the history of each buffer.

| Key | Command | What it does |
| --- | --- | --- |
| `⌃/`, `⌃x u`, `⌘z` | `undo` | Undo the last change |
| `⌘Z`, `⌃⌥_` | `undo-redo` | Redo the change that undo took back |

After a run of undos, the next `undo` reverses them: that is redo. `undo` takes a count like the motion commands, so `⌃u 3 ⌃/` undoes three steps.

Reference: [COMMANDS](<FURTHER READING/COMMANDS.md>), [C-u](<FURTHER READING/C-u.md>).

## The kill ring

Kill commands put text on the kill ring. `yank` puts the newest entry at point.

| Key | Command | What it does |
| --- | --- | --- |
| `⌃k` | `kill-line` | Kill from point to the end of the line |
| `⌃w` | `kill-region` | Kill the region |
| `⌥w` | `copy-region-as-kill` | Copy the region, without killing it |
| `⌥d` | `kill-word` | Kill forward to the end of the word |
| `⌥Backspace` | `backward-kill-word` | Kill backward to the start of the word |
| `⌃y` | `yank` | Paste the newest kill |
| `⌥y` | `yank-pop` | Replace the paste with an older kill |

A kill command that follows a kill command grows the newest entry. Three `⌃k` presses yank back as one piece.

The browser handles Cmd-C and Cmd-V. They use the system clipboard. The kill ring is separate and stays inside the editor.

Reference: [COMMANDS](<FURTHER READING/COMMANDS.md>).

## The mark ring

The mark is a saved place. A region is the text between the mark and point.

| Key | Command | What it does |
| --- | --- | --- |
| `⌃Space`, `⌥Space` | `set-mark-command` | Set the mark here |
| `⌃u ⌃Space` | `set-mark-command` | Go to the previous mark and pop the ring |
| `⌃x ⌃Space` | `pop-global-mark` | Go to the last mark set in any buffer |
| `⌃x ⌃x` | `exchange-point-and-mark` | Swap point and mark |

Each buffer keeps its own mark ring. A separate global ring goes back across buffers, so a jump can land in another file.

Reference: [COMMANDS](<FURTHER READING/COMMANDS.md>).

## Registers

A register is one character that holds text or a place.

| Key | Command | What it does |
| --- | --- | --- |
| `⌃x r Space` | `point-to-register` | Save point and the buffer |
| `⌃x r j` | `jump-to-register` | Go to the saved point, or restore saved windows |
| `⌃x r s` | `copy-to-register` | Save the region as text |
| `⌃x r +` | `append-to-register` | Add the region to the saved text |
| `⌃x r i` | `insert-register` | Insert the saved text at point |
| `⌃x r w` | `window-configuration-to-register` | Save the frame windows |
| `⌃x r v` | `view-register` | Say what a register holds |

Registers stay with the desktop, so they come back after a restart.

Reference: [COMMANDS](<FURTHER READING/COMMANDS.md>).

## Bookmarks

A bookmark has a name and a place. It lasts after a restart.

| Key | Command | What it does |
| --- | --- | --- |
| `⌃x r m` | `bookmark-set` | Set or replace a bookmark here |
| `⌃x r M` | `bookmark-set-no-overwrite` | Set a bookmark only if the name is free |
| `⌃x r b` | `bookmark-jump` | Go to a bookmark by name |
| `⌃x r l` | `list-bookmarks` | Show the bookmark table |

The bookmark table is a list. `Enter` visits the row, `/` filters, `Space` marks, `d` flags a bookmark for delete, and `x` deletes it.

Reference: [LISTS](<FURTHER READING/LISTS.md>), [HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## The prefix argument

`⌃u` sets one value for the next command only. The command reads it in one of two ways.

| Keys | Raw value |
| --- | --- |
| `⌃u` | `(4)` |
| `⌃u ⌃u` | `(16)` |
| `⌃u 3`, `⌥3` | `3` |
| `⌃u - 2` | `-2` |
| `⌥-` | `-` |

A count multiplies. `⌃u 8 ⌃n` moves eight lines. A flip is a yes or no, and the value does not matter. `⌃u` and `⌃u 17` mean the same.

The plain key is the common answer. `⌃u` asks for the other answer. Examples: `⌃x ⌃f` visits a file in this group, and `⌃u ⌃x ⌃f` asks which group. `⌃Space` sets the mark, and `⌃u ⌃Space` goes back to the previous mark.

The value belongs to the frame, so two browser tabs are two users. It also survives `⌥x`: `⌃u ⌥x foo` gives `foo` the same value that a key would.

Reference: [C-u](<FURTHER READING/C-u.md>), [COMMANDS](<FURTHER READING/COMMANDS.md>).

## Completion

Every prompt narrows its list as you type. The default match style is flex: one term is a subsequence, and several terms are substrings in any order.

| Key | What it does |
| --- | --- |
| `⌥p` | Put the previous remembered item in the input |
| `⌥n` | Put the next remembered item in the input |
| `Enter` | Choose the selected item |
| `⌃g` | Cancel the prompt |
| `⌥/` | Complete the text around point |
| `⌃⌥i` | Complete the text around point |

Each prompt keeps its own history across sessions. Some modes offer completion while you type. These settings control it:

| Setting | Default | Meaning |
| --- | --- | --- |
| `completion-auto` | `#t` | Offer completions while you type |
| `completion-auto-delay` | `150` | Milliseconds of quiet before it asks |
| `completion-auto-prefix` | `2` | Fewest characters before point |

Reference: [COMPLETION](<FURTHER READING/COMPLETION.md>).

## The two palettes

The editor has two ways to name a command.

| Key | Command | What it answers |
| --- | --- | --- |
| `⌥x` | `execute-extended-command` | What is the command called? |
| `⌘p` | `command-palette` | How do I do this? |

`⌥x` searches command names. Each row shows the key of the command, and the page shows what the command does. Type a part of the name and press `Enter`.

`⌘p` (Cmd-P) searches by the words of the task, including the everyday words people use. It puts the commands you ran first. Words that name no command go to a model, which picks one. A plain sentence can also bind a key, for example `bind C-x C-g k to group-kill`.

With `vscode-mode` on, Cmd-P finds a project file and Cmd-Shift-P (`⇧⌘p`) opens the palette. Run `⌥x vscode-mode` to toggle it.

For a plain search of the whole editor, press `⌃h a` (`apropos`). For a task, press `⌃h h` (`how-do-i`).

Reference: [COMMANDS](<FURTHER READING/COMMANDS.md>), [KEYMAPS](<FURTHER READING/KEYMAPS.md>).

## Menus

A transient is a short menu of related commands. It shows over the buffer, and the buffer stays selected. The menu owns the keys until you leave it.

| Key | What it does |
| --- | --- |
| `Enter` | Run the selected row |
| `Up`, `Down`, `⌃p`, `⌃n` | Select a row |
| `Left`, `Right` | Move between menu columns |
| `?` | Show the docstring of each row |
| `⌃g`, `Esc` | Close the menu |
| `⌃q` | Close every open menu |
| `⌃x ⌃s` | Save the menu settings |

Menus appear where a command has several values to set at once. `⌃c b` (`llm-configure`) is one: it sets the backend, the model and the effort. App modes use menus too, such as the todo actions and the tabs of a site app.

Reference: [KEYMAPS](<FURTHER READING/KEYMAPS.md>), [MODES](<FURTHER READING/MODES.md>).

## Text size

The size of the text belongs to the buffer.

| Key | Command | What it does |
| --- | --- | --- |
| `⌃+`, `⌘+` | `text-scale-increase` | Make this buffer larger |
| `⌃_`, `⌘_` | `text-scale-decrease` | Make this buffer smaller |
| `⌘)` | `text-scale-reset` | Give this buffer the normal size |
| `⌘=` | `ui-scale-increase` | Make the whole application larger |
| `⌘-` | `ui-scale-decrease` | Make the whole application smaller |
| `⌘0` | `ui-scale-reset` | Give the whole application the normal size |
| `⌃⌥+`, `⌃⌥=` | `content-scale-increase` | Show more of this buffer: one level in |
| `⌃⌥-` | `content-scale-decrease` | Show less of this buffer: one level out |
| `⌃⌥0` | `content-scale-reset` | Show this buffer at the normal level |

`text-scale` changes the font size of one buffer. `ui-scale` changes the size of every buffer in the frame. `content-scale` changes how much detail a structured buffer shows.

Reference: [HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## Visual line wrap

Long lines can wrap on the screen. `visual-line-mode` wraps them and makes the vertical motions follow the rows the reader sees, not the source lines.

- The mode is on in prose modes, such as morg and writing, and in web pages.
- There is no key. Run `⌥x visual-line-mode` to toggle it in the current buffer.
- `Up`, `Down`, `Home` and `End` move by rendered row. A run of vertical moves keeps the goal column.
- The browser measures where each row begins. Scheme decides what each key means.

Reference: [VISUAL-LINE-WRAP-MAP](<FURTHER READING/internal/VISUAL-LINE-WRAP-MAP.md>), [MODES](<FURTHER READING/MODES.md>).

## cua-mode

Shift with a motion key selects text. That is the whole of `cua-mode`, and it is on from boot.

| Key | Extends the region |
| --- | --- |
| `⇧←`, `⇧→` | One character |
| `⇧↑`, `⇧↓` | One visual line |
| `⇧Home`, `⇧End` | To the start or the end of the line |
| `⌃⇧←`, `⌃⇧→` | One word |
| `⌥⇧←`, `⌥⇧→` | One word on the macOS keyboard |
| `⌃⇧Home`, `⌃⇧End` | To the start or the end of the buffer |
| `⇧PageUp`, `⇧PageDown` | One screen |
| `⌘a` | The whole buffer |

Run `⌥x cua-mode` to toggle it.

The Shift chords work in a buffer you edit. In a buffer you have just landed on, they keep their plain meaning until the first key that says you are editing there. Press `Esc` or `⌃g` to return to that movement state.

A chat buffer refuses cua-mode. Use `⌃Space` to start a region there.

cua-mode does not own the Emacs keys. `⌃a`, `⌃e`, `⌃k`, `⌃f`, `⌃b`, `⌃n`, `⌃p`, `⌃d`, `⌥f`, `⌥b`, `⌃y`, `⌥w`, `⌃w` and `⌃Space` work in every buffer, and turning cua-mode off takes none of them away.

Reference: [cua-mode](<FURTHER READING/cua-mode.md>), [KEYMAPS](<FURTHER READING/KEYMAPS.md>).

## Vim keys

`evil-mode` gives the buffer Vim keys. Run `⌥x evil-mode` to toggle it everywhere, or `⌥x evil-local-mode` to toggle it in one buffer. To make it stick, put `(evil-mode-on!)` in `~/.compos/init.scm`.

- The states are normal, insert and visual. The cursor shows the state.
- Motions, operators, counts, `/` and `?` search, and the ex commands `:w`, `:q`, `:wq` and `:e FILE` work.
- Special buffers, such as chat, dired, mail and terminals, keep their own keys.
- The mode is not yet complete: repeat with `.`, macros, named registers and marks are not there.

Reference: [MODES](<FURTHER READING/MODES.md>), [KEYMAPS](<FURTHER READING/KEYMAPS.md>).

## For the agent

- Work on buffers by name. Do not move the user's windows, point, mark or focus.
- Use `⌥x` and `⌘p` to discover commands. Use `⌃h a` (`apropos`) to search the catalog, and `⌃h h` (`how-do-i`) for a task.
- Read a key with `(key-binding KEYS)`. Read every key of a command with `(where-is-internal COMMAND)`. The live editor wins over an older doc.
- A test names the command, never a production key. Bind your own keys to test a binding.
- The prefix argument is frame-local and lasts for one command. Read a count with `'p` and a flip with `'P`, never both.
- Add a setting with `defcustom` and read `docs/COMPONENTS.md` before you choose a menu.
- The full task list is in [HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>). The keys in force are in [KEYS](<FURTHER READING/manual/KEYS.md>). The rules of the keymap ladder are in [KEYMAPS](<FURTHER READING/KEYMAPS.md>).
