# Sessions and sharing

This chapter tells you how the editor keeps your work, how to return to it, and how to share it with another person or machine.

## Start here

- **Your work survives a restart.** Buffers, groups, window layouts, point, and scratch text come back after the editor starts again.
- **A browser tab is a frame.** Open as many tabs as you need. `Ctrl-x f` moves between frames.
- **One daemon is one editor with its own home.** `Ctrl-x d` lists the daemons and moves this tab to another one.
- **`Ctrl-c l` copies a link to this buffer and line.** A person who opens the link gets the editor at that place.
- **The phone client is `/m`.** It shows the same frame and talks to the same chat.

## What comes back

The editor saves the desktop to `~/.compos/desktop.etf`. A save records every group: its ID, its name, its members, its scratch text, and its layout for each frame.
A save also records every frame: the group it shows and the group it showed before.
A file buffer reopens its file. A buffer that is not a file keeps its text, its point, and its local settings.

Restore makes a best effort, and one bad group never stops the others. It drops a pane whose buffer is gone, rejects a layout it cannot read, recreates a missing scratch buffer, and folds an old membership list into one group. Restore never brings back a buffer that you killed.

Chats come back too, with their transcripts. The chat list keeps the conversations you archived. Press `A` there to show them.

| Command | What it does |
| --- | --- |
| `Option-x desktop-clear` | Empty the desktop, and ask about each modified file |

Reference: [groups](<FURTHER READING/groups.md>), [BUFFER](<FURTHER READING/BUFFER.md>).

## Restart the editor

`Option-x restart-daemon` saves the desktop, restarts the daemon, and loads the Scheme files again. The editor returns at the same place.

You do not need this command for normal work. A change to a Scheme or Elixir source file reloads when you save it. Use a restart only for four changes: a new dependency, a change to a supervision tree, a NIF rebuild, or a change that renames a door.

| Command | What it does |
| --- | --- |
| `Option-x restart-daemon` | Save the desktop and restart |

Reference: [manual/HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>), [ARCHITECTURE](<FURTHER READING/ARCHITECTURE.md>).

## Groups and frames

A group belongs to the desktop, not to a window. Each frame keeps its own group and its own previous group. Two tabs can show two groups, or one group with two arrangements. A group name and its ID do not change at a restart.

Frames share every group by default. An isolated frame shows only the groups it owns, and keeps them out of the other frames.

| Key or command | What it does |
| --- | --- |
| `Ctrl-x f` (`frame-switch`) | Move to another frame |
| `Ctrl-x g` (`group-switch`) | Pick a group for this frame |
| `Option-x frame-rename` | Give this frame a name |
| `Option-x frame-isolate` | Show only this frame's own groups |
| `Option-x group-send-to-frame` | Move this frame's group to another frame |

Reference: [groups](<FURTHER READING/groups.md>), [WINDOWS](<FURTHER READING/WINDOWS.md>).

## More than one editor

A daemon is one editor process. It has its own home directory, its own socket, its own desktop file, and its own peer id. Two daemons never share storage.

| Command | What it does |
| --- | --- |
| `Ctrl-x d` (`daemons`) | List the daemons; `Enter` moves this tab to one |
| `Option-x workspaces` | List the workspaces; `Enter` opens one in a new tab |
| `Option-x daemon-visit` | Move this tab to the daemon at point |

Each daemon restores its own frame and desktop. A workspace is a directory that a daemon serves. A new tab for a workspace restores only that workspace context.

Reference: [ARCHITECTURE](<FURTHER READING/ARCHITECTURE.md>).

## The phone

Open `/m` on the daemon. The phone is a second client of the same frame. It shows the selected window, the modeline, the group's chat, and the group tab rail. It sends the same key events as the desktop.

- A file buffer opens read-only.
- Any text that is not a key sequence or `Option-x NAME` goes to the group's chat.
- A link for a phone is `/m/b/NAME` with the same `?line=N` query.

Reference: [HANDHELD](<FURTHER READING/HANDHELD.md>).

## Share a link to a buffer

`Ctrl-c l` (`copy-buffer-link`) copies a link for the current buffer and line. The link has this shape:

```
http://localhost:4004/b/NAME?line=N
```

`NAME` is one percent-encoded path segment. A file buffer keeps the slashes of its path inside that segment. The line is in the query string because a fragment never reaches the daemon.

A person who opens the link gets the editor at that buffer and line. To read the text without the editor, open the same name under `/raw/`.

| Command | What it does |
| --- | --- |
| `Ctrl-c l` (`copy-buffer-link`) | Copy a link to this buffer and line |

Reference: [manual/HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>), [BUFFER](<FURTHER READING/BUFFER.md>).

## Two machines, one buffer

Two daemons can exchange the changes to one buffer. Each daemon has its own home, its own log, and its own peer id. Neither reads the other's disk.

`Option-x sync-buffer-with-peer` asks for the other daemon's socket. It sends what the other daemon is missing and takes what this one is missing. Both editors then hold the same text, and the history names both actors.

- A sync is manual. Nothing polls and nothing syncs in the background.
- The buffer is addressed by its name. Both machines must name the same buffer, and for a file that means the same path.
- Both copies must start from the same content. Two copies of one file with different roots merge into doubled text. The current code refuses only some of these cases, so check before you sync.

Reference: [PROVENANCE-CRDT](<FURTHER READING/PROVENANCE-CRDT.md>).

## Record a session

A recording holds a log of the visible windows and a video of the editor.

| Command | What it does |
| --- | --- |
| `Option-x recording-start` | Start the recording; with a prefix, choose the directory |
| `Option-x recording-end` | Stop the recording and name its log file |

The log records the active buffer and every window at each window change. The video is made from frames of the tab. Frame capture is on by default, at half scale and 30 frames a second.

Reference: [manual/COMMANDS](<FURTHER READING/manual/COMMANDS.md>).

## Screenshots

A screenshot is a PNG of one part of the editor. The default directory is `~/Desktop`, and the editor also puts the image on the clipboard.

| Command | What it does |
| --- | --- |
| `Option-x screenshot-frame` | Save the whole editor |
| `Option-x screenshot-window` | Save the selected window |
| `Option-x screenshot-target` | Save a buffer's window, a component, or a CSS selector |
| `Option-x screenshot-pick` | Point at a component, then click to save it |
| `Option-x screenshot-highlight` | Draw a box on a target for the next shot |
| `Option-x screenshot-path` | Show the path of the last screenshot |
| `Option-x screenshot-clear` | Remove every highlight box |

Reference: [manual/COMMANDS](<FURTHER READING/manual/COMMANDS.md>), [COMPONENTS](<FURTHER READING/COMPONENTS.md>).

## For the agent

- Do not restart a daemon that a person uses. Use `Option-x restart-daemon` when a restart is necessary, and never `pkill`.
- After a change, do not add a restart. A save reloads the Scheme file.
- Use `/raw/NAME` to read a buffer a user pastes as a link. Do not open the link in a window unless the user asks.
- The link name is one segment. Do not split it on its slashes.
- `(buffer-link)` prints a link. `(open-buffer-link! NAME LINE)` shows one.
- A peer sync needs separate homes and a manual call. Report the result of the sync, and do not claim that the editors follow each other.
- Recordings and screenshots are files. Name the path when you make one.
- The full rules for groups are in [groups](<FURTHER READING/groups.md>). The phone client is in [HANDHELD](<FURTHER READING/HANDHELD.md>). The CRDT work is in [PROVENANCE-CRDT](<FURTHER READING/PROVENANCE-CRDT.md>).
