What this is: Emacs rebuilt on the BEAM, scripted in Scheme, with a Phoenix LiveView frontend. Repo /Users/svs/src/ai-max.el, git-committed. Reference implementation being ported from: /Users/svs/src/aimax (Rust+Steel, read-only).

The one rule (never break it)

Elixir supplies mechanism. Scheme decides policy.

Loops over bytes, parsers, sockets, PTYs, NIFs → Elixir primitive. What a key means, what a command does, how something is presented → Scheme in apps/aimax_core/priv/*.scm. When adding a feature, ask first: can this be Scheme with one new primitive? Usually yes. Full detail in ARCHITECTURE.md.

Working rhythm (the user's expectations)

  • Be terse. Lead with the outcome; bullets; no recaps; no "verified" narration beyond one line. The user is recreating Emacs — don't hedge or over-flag.
  • Test everything, especially the Scheme kernel. Suite must stay green (mix test, currently 124 tests).
  • Verify in the real browser after each cycle, then commit.
  • Screenshot the window when UI changes — the user asks for this.
  • Use subagents for verification sweeps to keep context clean.

The dev loop

mix test                                   # all 4 apps
pkill -f "mix run"; sleep 1
(mix run --no-halt >> ~/.aimax/daemon.log 2>&1 &); sleep 6
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:4004/
git add -A && git commit -m "..."

A restart is required to reload priv/*.scm. The browser auto-reloads itself (boot-id mechanism) — no manual refresh needed.

Driving the browser (Chrome MCP tools)

The extension's type/key actions do not reach the editor — CDP text insertion emits no keydown events. Dispatch synthetic events instead, in short JS bursts (long loops freeze the renderer):

const send=(k,o={})=>window.dispatchEvent(
  new KeyboardEvent("keydown",{bubbles:true,key:k,...o}));
send("x",{ctrlKey:true}); send("f",{ctrlKey:true});   // C-x C-f
send("x",{altKey:true});                              // M-x

Known debt (honest list)

  • Scheme env frames are never GC'd — long sessions grow memory. Needs a reachability sweep.
  • Rope has no rebalancing and no line index; byte offsets only.
  • No macros (define-syntax) and no call/cc in the Scheme.
  • Modified-flag is version-based: undoing back to the saved state doesn't clear **.
  • RPC socket has no auth (localhost only).
  • Scheme grammar for tree-sitter not wired — .scm files aren't highlighted.
  • No test covers agent/RPC edits landing mid-undo-run.
  • MCP client speaks tools/resources/prompts only — no roots (+/-/= in mcp.el's hub) and no resource templates. A stdio server's stderr still goes to ~/.aimax/daemon.log, not to the hub's l log: merging it into the frame stream risks interleaving a half-written line into a JSON frame.

User's vision (keep this in view)

"Vibe coders will use it to get their hands dirty in the code." LSP, documentation rendered as beautiful HTML, visual mail — not like Emacs at all in presentation, but Emacs-true in its bones: everything programmable, everything a buffer, keyboard-first, transient windows. The HTML frontend isn't a compromise — it's the point.
