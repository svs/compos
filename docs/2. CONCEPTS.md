# Concepts

This file is for the agent. Use it to tell the user what compos is and how its parts fit. Speak in plain words. Each section names the reference in [FURTHER READING](<FURTHER READING/>) for more detail.

## What compos is

compos is a text editor that can run any app inside it. It works like Emacs: almost everything is a buffer, every action is a command, and the same keys work everywhere. The agent uses the same editor as the user, so both see the same things.

Reference: [INTRODUCTION](<FURTHER READING/INTRODUCTION.md>), [TUTORIAL](<FURTHER READING/TUTORIAL.md>), [LEARN COMPOS](<FURTHER READING/LEARN COMPOS.md>).

## Buffers

A buffer is content: a file, a chat, a directory listing, a help page, a mail thread, a web page, a list. A buffer can exist when no window shows it. Kill a buffer (`C-x k`) and its content goes.

Reference: [BUFFER](<FURTHER READING/BUFFER.md>), [KILL](<FURTHER READING/KILL.md>).

## Frame, layout, pane, window

The frame is the whole editor surface. A layout splits it into panes, a pane holds windows, and a window shows one buffer. Closing a window does not kill its buffers.

See [3. BUFFERS, PANES, WINDOWS](<3. BUFFERS, PANES, WINDOWS.md>) for the keys and the rules.

## Groups

A group is one task: a set of buffers and the layout you left them in. Groups work like the desktops of a tiling window manager. The tabs in the top bar are the groups. A buffer is in one group at a time, and a new buffer joins the current group. A group never shows a buffer of another group.

- `C-x g` switches to another group.
- `C-x C-g n` makes a new, empty group.

A group is a convenience, not a security boundary. A group also holds its chats, its todos and its working directory.

Reference: [groups](<FURTHER READING/groups.md>), [GROUP-MODES](<FURTHER READING/GROUP-MODES.md>).

## Modes

A major mode is a name, a setup function, a keymap and a hook. A buffer has one major mode and any number of minor modes. The mode decides what the keys do in that buffer. `M-x describe-mode` tells what the current buffer has.

Reference: [MODES](<FURTHER READING/MODES.md>).

## Commands and keys

A command is a name, a docstring and a function. `M-x`, a key, the palette (`Cmd-p`), an agent and a test all run a command by name. Type after `M-x` and the list narrows. A command with a key shows the key beside it.

A keymap maps keys to command names. A key goes down a ladder of keymaps: the thing at point, the minor modes, the buffer's mode, then the global map. `C-u` before a command gives it a prefix argument.

Reference: [COMMANDS](<FURTHER READING/COMMANDS.md>), [KEYMAPS](<FURTHER READING/KEYMAPS.md>), [C-u](<FURTHER READING/C-u.md>), [COMPLETION](<FURTHER READING/COMPLETION.md>).

## Lists

One list mode draws every table: ibuffer, dired, the chat list, the todos, feeds. So the same keys mark rows, filter, and act on marked rows, wherever the data comes from.

Reference: [LISTS](<FURTHER READING/LISTS.md>).

## Popups

Help pages, completions and other short-lived buffers are popups. `q` closes one, and what was under it comes back.

Reference: [POPUPS](<FURTHER READING/POPUPS.md>), [PEEK](<FURTHER READING/PEEK.md>).

## Scheme is the API

Elixir supplies the mechanism. Scheme decides the policy: what a key means, what a command does, how a buffer looks. The whole editor is scripted in its own Scheme, and the user's own Scheme lives in `~/.compos/*.scm`. This is why the agent can change almost anything while the editor runs.

Reference: [ARCHITECTURE](<FURTHER READING/ARCHITECTURE.md>), [BEAM-POWER](<FURTHER READING/BEAM-POWER.md>).
