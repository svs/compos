# Concepts

This chapter maps the ideas that compos is built from. Each part is short here, and each one has a chapter of its own. Read the map first, then open the chapter for the part you need.

## Start here

Tell a new user these five things first:

- Almost everything is a buffer: a file, a chat, a list, a web page.
- The frame is split into panes. A pane holds windows, and a window shows one buffer.
- A group is one task. It holds its buffers, its windows, its chats and its directory.
- Every action is a command. A key, `⌥x`, the palette and an agent all run a command by name.
- The editor is scripted in its own Scheme. So the agent can change almost anything while the editor runs.

## What compos is

compos is a text editor that can run any app inside it. It works like Emacs: almost everything is a buffer, every action is a command, and the same keys work everywhere. The agent uses the same editor as the user, so both see the same things.

Reference: [INTRODUCTION](<FURTHER READING/INTRODUCTION.md>), [TUTORIAL](<FURTHER READING/TUTORIAL.md>), [LEARN COMPOS](<FURTHER READING/LEARN COMPOS.md>).

## Buffers

A buffer is content: a file, a chat, a directory listing, a help page, a mail thread, a web page, a list. A buffer can exist when no window shows it. Kill a buffer (`⌃x k`) and its content goes.

Read [03. BUFFERS, PANES, WINDOWS](<03. BUFFERS, PANES, WINDOWS.md>) for the keys and the rules.

Reference: [BUFFER](<FURTHER READING/BUFFER.md>), [KILL](<FURTHER READING/KILL.md>).

## Frame, layout, pane, window

The frame is the whole editor surface. A layout splits it into panes, a pane holds windows, and a window shows one buffer. Closing a window does not kill its buffers.

Read [03. BUFFERS, PANES, WINDOWS](<03. BUFFERS, PANES, WINDOWS.md>) for the parts, the layouts and the keys.

Reference: [WINDOWS](<FURTHER READING/WINDOWS.md>), [PANES](<FURTHER READING/PANES.md>).

## Groups

A group is one task: a set of buffers and the layout you left them in. Groups work like the desktops of a tiling window manager. The tabs in the top bar are the groups. A buffer is in one group at a time, and a new buffer joins the current group. A group never shows a buffer of another group.

- `⌃x g` switches to another group.
- `⌃x ⌃g n` makes a new, empty group.

A group is a convenience, not a security boundary. A group also holds its chats, its todos and its working directory.

Read [03. BUFFERS, PANES, WINDOWS](<03. BUFFERS, PANES, WINDOWS.md>) for the keys. Reference: [groups](<FURTHER READING/groups.md>).

## Modes

A major mode is a name, a setup function, a keymap and a hook. A buffer has one major mode and any number of minor modes. The mode decides what the keys do in that buffer. `⌥x describe-mode` tells what the current buffer has.

Read [04. EVERYDAY EDITING](<04. EVERYDAY EDITING.md>). Reference: [MODES](<FURTHER READING/MODES.md>).

## Commands and keys

A command is a name, a docstring and a function. `⌥x`, a key, the palette (`⌘⇧p`), an agent and a test all run a command by name. Type after `⌥x` and the list narrows. A command with a key shows the key beside it.

A keymap maps keys to command names. A key goes down a ladder of keymaps: the thing at point, the minor modes, the buffer's mode, then the global map. `⌃u` before a command gives it a prefix argument.

Read [04. EVERYDAY EDITING](<04. EVERYDAY EDITING.md>). Reference: [COMMANDS](<FURTHER READING/COMMANDS.md>), [KEYMAPS](<FURTHER READING/KEYMAPS.md>), [C-u](<FURTHER READING/C-u.md>), [COMPLETION](<FURTHER READING/COMPLETION.md>).

## Lists

One list mode draws every table: ibuffer, dired, the chat list, the todos, feeds, apps. So the same keys mark rows, filter, and act on marked rows, wherever the data comes from.

Read [04. EVERYDAY EDITING](<04. EVERYDAY EDITING.md>) for the keys, and [10. APPS](<10. APPS.md>) for an app built from a list and a page. Reference: [LISTS](<FURTHER READING/LISTS.md>).

## Popups

Help pages, completions and other short-lived buffers are popups. `q` closes one, and what was under it comes back.

Read [04. EVERYDAY EDITING](<04. EVERYDAY EDITING.md>). Reference: [POPUPS](<FURTHER READING/POPUPS.md>), [PEEK](<FURTHER READING/PEEK.md>).

## One word, one thing

Each word below names one thing in compos. The other things use other words.

| Word | What it is | Not this |
| --- | --- | --- |
| group | One task: a set of buffers and the layout you left them in. | a pane, a window |
| pane | One part of the frame. The layout makes the panes. | a window |
| window | One view of a buffer in a pane. A pane holds a stack of windows, and one window is at the front. | a pane, a browser window |
| group tab | The tab of a group in the top bar. | a browser tab |
| browser tab | A tab of your web browser. `⌥x switch-to-tab` brings one to the front. | a group tab |
| browser window | A window of your web browser. `⌥x browsers` lists them and their tabs. | a window |
| view tab | A tab in the header of a list or a detail page. It changes the view of the same buffer. | a browser tab |
| `TAB` | The key. It indents or completes. | a tab |
| worktree | A Git worktree for one coding task. `⌥x worktree-manage` lists them. | a session |
| session | One daemon that serves one worktree or group. `⌥x sessions` lists them, and `⌃x D` lists the daemons. | a worktree |
| keys | Key bindings. `⌃h B` (`keys`) shows every key in force here. | secrets |
| secrets | API keys, passwords and tokens. Their settings are in the `secrets` customize group. | key bindings |

The lists of these things:

| Command | What it lists |
| --- | --- |
| `⌥x groups` | Every group |
| `⌃x w` (`panes-list`) | The panes of this group and their windows |
| `⌥x windows-list-ring` | Every window of the frame, in one flat list |
| `⌥x pane-overview` | The windows of this pane, as tiles in the pane |

## Scheme is the API

Elixir supplies the mechanism. Scheme decides the policy: what a key means, what a command does, how a buffer looks. The whole editor is scripted in its own Scheme, and the user's own Scheme lives in `~/.compos/*.scm`. This is why the agent can change almost anything while the editor runs.

Read [13. EXTEND](<13. EXTEND.md>) for your own Scheme, and [15. UNDER THE HOOD](<15. UNDER THE HOOD.md>) for the architecture. Reference: [ARCHITECTURE](<FURTHER READING/ARCHITECTURE.md>), [BEAM-POWER](<FURTHER READING/BEAM-POWER.md>).
