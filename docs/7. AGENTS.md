# Agents

This file is for the agent. Use it to tell the user how chats and agents work in compos.

## Chats

A chat is a buffer. You type at the bottom and the agent answers in the same buffer. A chat belongs to a group, and it works in that group's directory.

- `M-x chat-new` starts a chat.
- `M-x chat-list` lists every chat, live and saved. It is a normal list: mark, filter, act.
- `C-x l +` gives a layout with the group's chat in a narrow pane.
- `M-x chat-abort` stops the turn that runs now.

Reference: [CHAT-LIST](<FURTHER READING/CHAT-LIST.md>), [TUTORIAL](<FURTHER READING/TUTORIAL.md>).

## How an agent acts

The agent does not click or guess. It runs Scheme in the live editor through the compos MCP server. With Scheme it reads and edits buffers, runs commands and finds the API with `apropos`. It works on buffers by name and does not move the user's point, windows or focus.

The agent knows what the user sees. When the user says this, the agent looks at the visible buffers. So the user can point at a buffer and ask about it.

Reference: [EMACS-AS-AGENT-HARNESS](<FURTHER READING/EMACS-AS-AGENT-HARNESS.md>), [BEYOND-TOOLS](<FURTHER READING/BEYOND-TOOLS.md>), [PROMPTS](<FURTHER READING/PROMPTS.md>).

## Connectors, models, presets, bundles

- A **connector** is the backend that runs the agent, for example Claude Code, Codex, OpenCode or a direct API.
- A **preset** is one capability: MCP servers, a prompt on how to use them, and the names the agent finds first.
- A **bundle** is a whole chat setup: connector, model, effort, permissions and presets, saved under a name and a key.
- A **group** says which bundle its new chats start with.

`C-c b` (`M-x llm-configure`) edits all of this.

Reference: [AGENT CONTEXT MANAGEMENT](<FURTHER READING/AGENT CONTEXT MANAGEMENT.md>).

## Todos

The user and every agent share one todo list. `M-x todo` opens it. A todo can start an agent chat that works on it, and the todo keeps the goal, the notes, the status and the log. The task is the record, not the chat.

## Events

Everything that happens outside a keystroke goes to one event log: a mail came in, an agent finished a turn, a workflow ran. Workflows and agents listen to it. So an agent can start slow work, end its turn, and wake when the work is done.

Reference: [EVENT BUS](<FURTHER READING/EVENT BUS.md>).
