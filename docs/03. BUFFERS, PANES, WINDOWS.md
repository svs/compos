# Buffers, panes, windows

This file is for the agent. Use it to tell the user how the screen works: what they see, where a new buffer goes, and how to get things back. Speak in plain words and give the keys.

## Start here

Tell a new user these first:

- The frame is one browser tab. A layout splits it into panes, and a pane holds windows.
- A window shows one buffer, with its own point and scroll.
- A group is one task: its buffers, its windows and its directory. The tabs at the top are the groups.
- `⌃x o` moves to the next window, `⌃x 0` closes a window, and `⌃x k` kills a buffer.
- Closing a window does not kill its buffers. `q` goes back to what the window showed before.

## The parts, from the outside in

| Part | What it is |
| --- | --- |
| **Frame** | The whole editor surface: one browser tab or one app window. |
| **Group** | One task: its buffers and its windows. The tabs in the top bar are the groups. |
| **Layout** | The shape of the frame: one pane, two panes, three columns, rows, or free. |
| **Pane** | A place on the screen, for example left or right. A pane holds windows. |
| **Window** | Shows one buffer. It keeps its own point and scroll. |
| **Buffer** | The content: a file, a chat, a list, a help page, a web page. |

Almost everything is a buffer, so the same keys work on all of them.

Reference: [WINDOWS](<FURTHER READING/WINDOWS.md>), [windows-guide.svg](<assets/windows-guide.svg>).

## Buffers

- A buffer exists once in the editor and is in one group at a time.
- A buffer can be open with no window that shows it.
- Two windows can show the same buffer, each at its own place. But when you show a buffer in a window, another window of the frame that shows it moves to a different buffer, if one is free. When no other buffer is free, both windows keep it. A preview never moves it, and other frames are not touched.
- A file buffer follows its file. When git, a formatter or another program changes the file, the editor merges that change into the buffer and keeps the user's unsaved work. A save also merges first. Only a line that both sides changed stops the save; `⌥x save-buffer-anyway` then writes over the file.
- `⌥x buffer-rename` gives a buffer a new name. Its file stays the same.

| Key | What it does |
| --- | --- |
| `⌃x b` | Pick a buffer to show here |
| `⌃x ⌃b` | List every buffer, by group (ibuffer) |
| `⌃x Left`, `⌃x Right` | Show the previous or next buffer in this window |
| `` ⌃` `` | Next buffer of the same mode in this group |
| `⌃x k` | Kill a buffer |

Reference: [BUFFER](<FURTHER READING/BUFFER.md>), [FILE-VIEW](<FURTHER READING/FILE-VIEW.md>).

## Windows are stacks

A window remembers the buffers it showed, in order. You see the one on top. Open a help page over the tutorial, press `q`, and the tutorial comes back at the same place. Each window has its own stack, and closing never brings a buffer back from another window.

A pane also holds a stack: one window is on the screen, and the others wait behind it.

Reference: [PANES](<FURTHER READING/PANES.md>).

## Closing is not killing

- **Close a window** (`⌃x 0`): the window leaves the screen. Its buffers stay open.
- **Quit a buffer** (`q` on a help page, a list or a popup): the buffer under it in that window comes back.
- **Kill a buffer** (`⌃x k`): the content goes. Each window that showed it shows its own previous buffer. The layout stays.

When a window has no previous buffer left, it shows the group's chat, or it closes. compos does not fill an empty window with a scratch buffer.

Reference: [KILL](<FURTHER READING/KILL.md>).

## Moving between windows

| Key | What it does |
| --- | --- |
| `⌃x o` | Next window |
| `⌘←`, `⌘→` | Window on the left or the right |
| `⌃x 3`, `⌃x 2` | Split side by side, or one above the other |
| `⌃x 0` | Close this window |
| `⌃x 1` | Keep only this window |
| `⌥↓` / `⌥↑` | Scroll the other window and stay here |

## Layouts

`⌃x l` chooses a layout, then one key:

| Key | Layout |
| --- | --- |
| `1` | One window |
| `2` | Two panes, 2/3 and 1/3 |
| `=` | Two equal panes |
| `c` | Three columns |
| `r` | Two rows |
| `+` | Two equal panes and the group chat in a narrow pane |
| `f` | Free: you split by hand |

A new group starts with three columns. A layout only arranges the windows the group has; it does not open buffers to fill a pane. When a layout has fewer panes, the extra windows wait off the screen. Go back to more panes and they come back as they were.

`⌃c Left` puts back the previous arrangement of windows, and `⌃c Right` goes forward again.

Reference: [PANES](<FURTHER READING/PANES.md>), [WINDOWS](<FURTHER READING/WINDOWS.md>).

## Where a new buffer goes

The place follows from what the user did, not from what the buffer is:

- **Open a file or run a command that opens one thing**: it shows in the window you are in.
- **Open a row from a list** (dired, ibuffer, search results): it shows in the other window. The list stays.
- **Open a row that has its own detail page** (a Sentry issue, a WhatsApp chat): it shows in the list's detail window, and later rows use that same window.
- **One window per mode**: a group shows one window for each major mode. A second chat takes the chat window, so the group never shows two chats side by side.
- **Groups never mix**: a window never shows a buffer of another group, and a layout never takes a window from another group.

Reference: [DISPLAY-BUFFER](<FURTHER READING/DISPLAY-BUFFER.md>), [groups](<FURTHER READING/groups.md>).

## Peek and popups

- **Peek**: in a list, look at the row at point in a real window. `n` and `p` peek the next and previous row, `Enter` keeps it, `q` dismisses it and puts the list back.
- **Popup**: a short-lived buffer, such as messages or help, at the edge of the frame. No buffer is a popup until the user names it in `popper-reference-buffers`. `` ⌥` `` shows the next popup. `⌃⌥<arrow>` moves it to another edge. `` ⌃⌥` `` makes a popup an ordinary buffer, or an ordinary buffer a popup. `q` closes it and never kills it.

Reference: [PEEK](<FURTHER READING/PEEK.md>), [POPUPS](<FURTHER READING/POPUPS.md>).

## For the agent

- Work on buffers by name. Do not move the user's windows, point or focus.
- Show a file only when the user asks, and in the other window.
- The full rules and test cases are in [WINDOWS-SPEC](<FURTHER READING/internal/WINDOWS-SPEC.md>). Not every case there is checked.
