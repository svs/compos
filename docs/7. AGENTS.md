# Agents

This chapter tells how chats and agents work in compos: how to start one, how it acts, how to answer it, and how it sees your work.

## Start here

Tell a new user these first:

- A chat is a buffer. Type at the bottom and the agent answers in the same buffer.
- `RET` sends. `C-g` stops the reply that runs now. `S-RET` starts a new line.
- The agent does not click or guess. It runs Scheme in the same live editor, so it reads and edits buffers, runs commands and finds the API.
- It knows what you see. When you say this, it looks at the visible buffers and the buffers of your group.
- `C-c b` sets the connector, the model and the tools. `C-c p` sets when the agent stops to ask you.

## Chats

A chat belongs to a group, and it works in that group's directory. The group says which model its new chats start with.

| Key | Does |
| --- | --- |
| `C-c n` | Start a new chat |
| `RET` | Send what you typed |
| `C-RET` | Send the input next, ahead of the queue |
| `S-RET` | Start a new line |
| `C-g` | Stop the reply that runs now |
| `C-c C-k` | Reset the chat: clear the transcript, keep the model |
| `C-c m` | Choose the model |
| `C-c $` | Show what this chat cost |
| `C-c b` | Set the connector, model, effort, tools and prompt sections |
| `C-c t` | File this chat as a todo |

`M-x chat-list` (`C-x C-c`) lists every chat, live and saved. `C-x l +` gives a layout with the group's chat in a narrow pane. `C-x 1` keeps only this window.

Reference: [CHAT-LIST](<FURTHER READING/CHAT-LIST.md>), [TUTORIAL](<FURTHER READING/TUTORIAL.md>), [SIMPLIFY-SPEC](<FURTHER READING/SIMPLIFY-SPEC.md>).

## The chat list

The chat list is a normal list. It shows the live chats first, and the archived ones at the bottom.

| Key | Does |
| --- | --- |
| `RET` | Enter the chat at point, or read an archived one back |
| `SPC` | Mark the row at point |
| `/` | Narrow on every key; `/` again has a Status tab |
| `f` | Filter every chat by title, state, model or a word in it |
| `<`, `>` | Cycle the sections and the order |
| `s` | Send a steering message to the chat or the marked chats |
| `y`, `d` | Allow or deny the pending permission |
| `r` | Give the chat a title |
| `k`, `a`, `D` | Kill, archive or delete |
| `+` | Start a chat |
| `w` | Watch the list: the busiest chat first, kept up as chats change |
| `.` | Show or hide the chats an agent started for itself |
| `A` | Show the 100 newest archived chats alone |
| `g`, `q` | Read the chats again, or give the frame back |

The list previews a row beside itself as you move. `RET` enters the chat and leaves the point and the focus in the list.

Reference: [CHAT-LIST](<FURTHER READING/CHAT-LIST.md>), [LISTS](<FURTHER READING/LISTS.md>).

## Permission answers

A chat has one stance. `C-c p` cycles it:

| Stance | What asks |
| --- | --- |
| `approve` | Only an irreversible act asks |
| `auto` | The same, and the deny-list still holds |
| `ask` | Every tool call asks |

When a call waits for you, answer in the chat:

| Key | Does |
| --- | --- |
| `C-c C-y` | Allow this call once |
| `C-c C-a` | Allow it and stop asking for this tool |
| `C-c C-n` | Deny it |

In the chat list, `y` and `d` answer the pending permission of the chat at point. `C-c a a` jumps to the first thread that needs you: a permission, a question, or a blocked chat.

Reference: [SIMPLIFY-SPEC](<FURTHER READING/SIMPLIFY-SPEC.md>).

## Context: visible buffers, companions, group members

The agent starts every chat with a context block. It names the chat, the group, the directory, the connector, the model, the companions, the group members and the visible buffers. So the agent spends no tool round to ask.

- Visible buffers: the buffers on the screen, the last used first, with the mode and the line at point. `editor-context-snapshot` sends one line for each; set it to `#f` to send none.
- Companions: every buffer of the group that is not a chat. A new file in the group sends the block again.
- Group members: the buffers in the chat's own group.

The block rides again only when the group, the directory or the companions change. The agent calls `(chat-context)` when the block is missing or when your work changes.

When you say this, the agent reads the first buffer you see that is not the chat. To point at another buffer, name it or show it.

| Key | Does |
| --- | --- |
| `C-c w` or `C-c c` | Toggle between a work buffer and its group chat |
| `C-c RET` | Ask the group's chat about this buffer without leaving it |
| `M-o` | Open this document's own chat, or start one |
| `C-c C-v` | Switch between the rich and the plain transcript |

`M-x chat-compact` summarizes the older turns and keeps the recent ones, when a chat gets long. `M-x chat-show-prompt` shows the prompt the chat carries.

Reference: [AGENT CONTEXT MANAGEMENT](<FURTHER READING/AGENT CONTEXT MANAGEMENT.md>), [PROMPTS](<FURTHER READING/PROMPTS.md>).

## Steering and the queue

You do not wait for a turn to end to speak. If a turn runs, a message that arrives joins it as steering. If the connector cannot steer, the message waits in the queue.

- `RET` sends. During a turn it steers or queues.
- `C-RET` sends the input next, ahead of what already waits.
- `C-c C-d` removes the oldest queued message.
- `s` in the chat list steers the chat at point, or the marked chats.

The model sees a steering message inside the running turn, so it can change course before it answers.

## Subagents

An agent can start other chats for parts of its work. A spawned chat names the chat that spawned it, and the edge outlives both buffers.

| Key | Does |
| --- | --- |
| `C-c a n` | Prompt for a task and spawn a new agent thread |
| `M-x subagents` | List every spawn edge: parent, child, status and the child's last line |

The list shows `running`, `your turn`, `idle`, `stopped`, `done` and `gone`. `RET` shows the row's chat and leaves the point in the list. `g` reads the edges again.

Reference: [EMACS-AS-AGENT-HARNESS](<FURTHER READING/EMACS-AS-AGENT-HARNESS.md>), [BEYOND-TOOLS](<FURTHER READING/BEYOND-TOOLS.md>).

## Skills

A skill is a file of working instructions. The agent loads one by name with `(skill NAME)`, and the instructions join its prompt for that task.

- Type `/NAME` at the start of a chat message to run a skill by name.
- `M-x chat-show-skills` opens dired on the skills this chat can load.
- Skills live in `priv/skills` and `~/.compos/skills`, and in a group's `.claude/skills`.

A skill can carry its own Scheme in one fenced `scheme run` block. The agent runs that block, or the skill's prose when it has no block.

Reference: [LEARN COMPOS](<FURTHER READING/LEARN COMPOS.md>), [AGENT CONTEXT MANAGEMENT](<FURTHER READING/AGENT CONTEXT MANAGEMENT.md>).

## Prompts

The system prompt is made of named sections: one section for each Markdown file, plus the generated `catalog`, `mcp`, and the parts a mode adds.

- `C-c b`, then `+`, then `i` shows the sections as switches, in prompt order.
- `x` applies the switches. `a` selects all, `n` selects none, and `C-g` discards the draft.
- `M-x chat-show-prompt` marks the live composition with `-` and `o`, and shows its bytes.
- `M-x chat-refresh-prompt` replaces the frozen prompt from the current sources.

The first send freezes the prompt, so later turns reuse the same bytes and the cache stays warm. A bundle records the sections it turns off. A preset adds a section after `mcp`.

Reference: [PROMPTS](<FURTHER READING/PROMPTS.md>), [AGENT CONTEXT MANAGEMENT](<FURTHER READING/AGENT CONTEXT MANAGEMENT.md>).

## Tool results

A tool call and its result show as one block in the transcript. The agent reads the result in the same conversation, and acts on it in the same turn.

| Key | Does |
| --- | --- |
| `TAB` | Fold or open the tool output at point |
| `C-c C-v` | Switch between the rich and the plain transcript |
| `M-x chat-heal` | Drop tool calls and results that lost their other half |
| `M-x chat-refresh-tools` | Adopt the editor's current tool list in this chat |
| `M-x chat-tool-surface` | Show the MCP servers this chat's agent holds |

The agent reads edit results as a diff, and schemas as data. It never has to parse a printed line.

Reference: [BEYOND-TOOLS](<FURTHER READING/BEYOND-TOOLS.md>), [SIMPLIFY-SPEC](<FURTHER READING/SIMPLIFY-SPEC.md>).

## Abort, unstick, heal

A turn can stop in three places, and each has its own repair.

| Command | When | Does |
| --- | --- | --- |
| `C-g` / `M-x chat-abort` | A reply is in flight | Stop it; the transcript keeps what arrived |
| `M-x chat-unstick` | The chat shows a turn that no runtime runs | Clear the turn and land its end |
| `M-x chat-heal` | A tool call lost its result, or a result lost its call | Drop the orphan blocks |
| `C-c C-k` | The conversation is stale | Clear the transcript and keep the model |
| `M-x agent-interrupt-send` | The agent is dead or stuck | Revive it, cancel it, or hard-reset it |

`M-x chat-unstick` refuses a live turn and tells you that `C-g` cancels it. It never lands a turn twice.

Reference: [SIMPLIFY-SPEC](<FURTHER READING/SIMPLIFY-SPEC.md>).

## Todos and events

The user and every agent share one todo list. `M-x todo` opens it. A todo can start an agent chat that works on it, and the todo keeps the goal, the notes, the status and the log. The task is the record, not the chat.

Everything that happens outside a keystroke goes to one event log: a mail came in, an agent finished a turn, a workflow ran. Workflows and agents listen to it. So an agent can start slow work, end its turn, and wake when the work is done.

Reference: [9. TODOS + WORKFLOWS](<9. TODOS + WORKFLOWS.md>), [EVENT BUS](<FURTHER READING/EVENT BUS.md>).

## For the agent

- Work on buffers by name. Do not move the user's windows, point or focus.
- Show a file only when the user asks, and in the other window.
- Read the visible context before you answer a question about this. It names the group, the companions and the visible line of each buffer.
- Answer a permission at once when the user asks for it. Do not guess what the user wants and click through.
- Use a steering message to change your own course, and `C-RET` only when the next message must go first.
- When a tool result is missing or the record is broken, call `M-x chat-heal` or `M-x chat-unstick` and report what it did.
- Load a skill before the work it covers. The skills are the durable instructions, and the chat is not.
