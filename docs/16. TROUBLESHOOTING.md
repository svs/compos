# Troubleshooting

This chapter helps when something does not work: ask the editor, read the messages, stop a stuck chat, find a freeze, measure performance, and report a problem.

## Start here

- Press `⌃h k` (`describe-key`), then a key, to learn what it does.
- Press `⌃h e` (`view-messages`) to see what the editor said, with errors first.
- Press `⌃h ?` (`help-for-help`) for every help command and every task.
- If a chat does not answer, press `⌥x chat-abort`.
- Tell the agent what you did and what you saw. It reads the buffers, the messages, and the code, and it can fix the problem while the editor runs.

## Ask the editor

| Key or command | What it answers |
| --- | --- |
| `⌃h k` (`describe-key`) | What this key does, and which keymap binds it |
| `⌃h b` (`describe-bindings`) | Every key that works in this buffer |
| `⌃h m` (`describe-mode`) | This buffer's mode and its keys |
| `⌃h a` (`apropos`) | Commands, functions, settings, and modes that match words |
| `⌥?` (`contextual-help`) | The name at point, this buffer, its mode, and its keys |
| `⌃h h` (`how-do-i`) | Pick a task and read how to do it |
| `⌃h B` (`keys`) | Every key in force here, and the edits |
| `⌥x describe-variable` | What a setting is and what it holds |
| `⌥x view-messages` | The editor's messages and errors |

Reference: [manual/HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## Messages

The echo area shows the last message. The `*Messages*` buffer keeps every one, with errors first in their colour.

- `⌃h e` (`view-messages`) opens the buffer.
- `⌥x messages-clear` empties it.
- `⌥x messages-filter-level`, `⌥x messages-filter-group`, and `⌥x messages-filter-project` narrow it.

A message is the first evidence. Read it before you change anything.

Reference: [manual/HOW-DO-I](<FURTHER READING/manual/HOW-DO-I.md>).

## A chat does not answer

- `⌥x chat-abort` stops the turn that runs now. Press it again if the chat still holds the lane.
- `⌃c b` (`⌥x llm-configure`) shows the connector, the model, and the effort of this chat.
- `⌥x llm-connectors` shows every connector and tests it. `⌥x setup` reconnects one.
- `⌥x mcp-status` shows the MCP servers the chat holds. `⌃c a m` (`⌥x mcp-hub`) restarts one that is down.
- A long turn may only be slow. `⌥x chat-perf` shows every step of the last turn, with a flame graph.

See [01. SETUP](<01. SETUP.md>) to connect a model again.

Reference: [AGENT CONTEXT MANAGEMENT](<FURTHER READING/AGENT CONTEXT MANAGEMENT.md>).

## The editor is slow or freezes

- `⌥x perf` shows lane contention: the wait and the work of every lane.
- `⌥x profile` profiles the next command and shows where its time went.
- `⌥x chat-perf` shows the steps of this chat's last turn.
- `⌥x telemetry` lists the slow events.
- `⌥x debug-window-movements` shows the last ten changes of this frame's windows. Use it when the layout thrashes.

A slow agent turn, a large file, or a grammar that has not loaded is the usual cause, not a dead editor. Wait for the echo area before you restart.

Reference: [ARCHITECTURE](<FURTHER READING/ARCHITECTURE.md>), [BEAM-POWER](<FURTHER READING/BEAM-POWER.md>).

## A change does not appear

- Save the file. The editor hot-reloads a changed `.scm` or `.ex`, and the echo area states the result. Do not restart to see a change.
- Use `⌥x reload-file` for a file outside the watched roots.
- Use `⌥x restart-daemon` only for four changes: a new dependency, a change to a supervision tree, a NIF rebuild, or a change that moves a registration or renames a door. It saves the desktop first.
- After a Scheme change, check the live daemon holds it: `(boundp 'NAME)` and `(key-binding KEYS)` in a buffer of the mode.
- Never `pkill` a daemon. The tree can hold other sessions and other worktrees.

Reference: [ARCHITECTURE](<FURTHER READING/ARCHITECTURE.md>).

## Errors and provenance

- The echo area shows the last error; `⌃h e` shows every one.
- An `eval-scheme` call that raises rolls back the whole form. Side effects earlier in the form do not survive.
- `⌥x buffer-log` shows the provenance of this buffer: every accepted revision.
- `⌥x setup-report` gives a setup status report. It holds no secret values.
- Some tests were red before a change. [KNOWN-FAILURES](<FURTHER READING/internal/KNOWN-FAILURES.md>) lists them, so you can tell a regression from the weather. It is evidence, not permission.

## How to report

Give three things: what you did, what you saw, and the exact error text.

1. `⌃h e` (`view-messages`) for the messages and errors.
2. `⌃c l` (`copy-buffer-link`) for a link to the buffer and line.
3. `⌥x setup-report` for the setup state, with no secrets.

Then tell the agent. It can read the buffers, the messages, and the code, and it can fix the problem while the editor runs. For a defect in compos itself, give the same three things to the person who maintains your compos.

Reference: [KNOWN-FAILURES](<FURTHER READING/internal/KNOWN-FAILURES.md>), [SCHEME-GOTCHAS](<FURTHER READING/SCHEME-GOTCHAS.md>).

## For the agent

- Reproduce before you explain. Read the messages, the buffer, and the code.
- Do not restart a daemon that a person uses. Boot an isolated one with its own `COMPOS_HOME`, `COMPOS_PORT`, and `COMPOS_APP_PORT`, then shut it down.
- Read [KNOWN-FAILURES](<FURTHER READING/internal/KNOWN-FAILURES.md>) before you call a red test a regression.
- Measure with `(monotonic-ms)` on both sides of a slow call, and report the elapsed number.
- After a fix, read the affected state back. After a revert, restart instead of trusting the reload.
- Go deeper: [KNOWN-FAILURES](<FURTHER READING/internal/KNOWN-FAILURES.md>), [SCHEME-GOTCHAS](<FURTHER READING/SCHEME-GOTCHAS.md>), [SIMPLIFY-AUDIT](<FURTHER READING/internal/SIMPLIFY-AUDIT.md>), [CLEANUP-QUEUE](<FURTHER READING/internal/CLEANUP-QUEUE.md>), [TESTING](<FURTHER READING/TESTING.md>).
