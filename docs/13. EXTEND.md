# Extend

This file is for the agent. Use it to tell the user how compos grows: new commands, modes and apps, all in Scheme.

## The rule

Elixir supplies the mechanism. Scheme decides the policy. So a new feature is almost always Scheme: a command, a mode, a keymap, a hook or a view. The editor packages are in `scheme/packages/`. The user's own are in `~/.compos/`.

Reference: [ARCHITECTURE](<FURTHER READING/ARCHITECTURE.md>).

## The parts

- **Command**: `define-command` gives it a name, a docstring and a function. Reference: [COMMANDS](<FURTHER READING/COMMANDS.md>).
- **Mode**: a name, a setup function, a keymap and a hook. Reference: [MODES](<FURTHER READING/MODES.md>).
- **Keymap**: Reference: [KEYMAPS](<FURTHER READING/KEYMAPS.md>).
- **Hook**: Reference: [HOOKS](<FURTHER READING/HOOKS.md>).
- **UI component**: a ready view, such as a table or a card. Use one from the catalog before you make a new one. Reference: [COMPONENTS](<FURTHER READING/COMPONENTS.md>), [COMPOSML](<FURTHER READING/COMPOSML.md>), [COMPOSML-COMPONENTS](<FURTHER READING/COMPOSML-COMPONENTS.md>).
- **Fenced block**: a code block in a buffer that has its own kind and keys. Reference: [BLOCKS](<FURTHER READING/BLOCKS.md>), [MARKDOWN](<FURTHER READING/MARKDOWN.md>).
- **Workflow**: Scheme that reacts to events. Reference: [EVENT BUS](<FURTHER READING/EVENT BUS.md>).

## Try it live

`M-x eval-expression` runs one Scheme expression in the editor. A change takes effect at once, with no restart.
